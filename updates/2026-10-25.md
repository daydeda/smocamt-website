# ActiveCAMT v2.33.1 🎉

# อัปเดต ActiveCAMT ประจำวันที่ 25 ต.ค. 69

สรุปสำหรับวันที่ 25 ต.ค. 69 เอาไว้ลง Discord และให้ทีมที่เกี่ยวข้องอ่านกัน

---

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **ชื่อแยกเป็นช่อง:** ตอนกรอกข้อมูลส่วนตัวและในหน้าโปรไฟล์ ชื่อถูกแยกเป็น ชื่อ, ชื่อกลาง (ถ้ามี) และนามสกุล แทนช่องชื่อ-นามสกุลช่องเดียว
- **คนไทยกรอกชื่อเป็นภาษาไทย:** มีกล่องแจ้งเตือนสีฟ้าเป็นภาษาไทยเสมอ แม้จะเปลี่ยนภาษาของเว็บเป็นอย่างอื่น ถ้าพิมพ์ชื่อเป็นตัวอักษรอังกฤษ ระบบจะเตือนทันที นักศึกษาต่างชาติกดปุ่ม "I'm an international student, keep English" เพื่อใช้ชื่ออังกฤษได้ในคลิกเดียว
- **ห้ามตัวเลขและอักขระพิเศษในชื่อ:** ชื่อ ชื่อกลาง นามสกุล และชื่อเล่น ใส่ได้เฉพาะตัวอักษร ช่องว่าง ขีดกลาง จุด และอะพอสทรอฟี ตัวเลขกับสัญลักษณ์อย่าง `* & , / |` จะถูกตัดออกทันทีที่พิมพ์หรือวาง
- **ผู้ติดต่อฉุกเฉินเริ่มที่ 1 คน:** หน้าผู้ติดต่อฉุกเฉินแสดงการ์ดเดียวก่อน และมีข้อความบอกว่ากรอก 1 คนก็เพียงพอ ถ้าอยากเพิ่มคนที่ 2 กดปุ่ม "เพิ่มผู้ติดต่อฉุกเฉินอีกคน" และลบออกได้ภายหลัง
- **ผู้ติดต่อฉุกเฉินแยกชื่อเช่นกัน:** กรอก ชื่อ, ชื่อกลาง (ถ้ามี), นามสกุล และชื่อเล่น (ถ้ามี) และใช้กติกาภาษาไทยเดียวกับชื่อของตัวเอง ถ้าผู้ติดต่อไม่ใช่คนไทยกดยืนยันใช้ภาษาอังกฤษได้เฉพาะคนนั้น
- **เลข HN (ไม่บังคับ):** ในขั้นตอนข้อมูลสุขภาพ ใส่เลขประจำตัวผู้ป่วย (Hospital Number) ของโรงพยาบาลที่รักษาประจำได้ พร้อมชื่อโรงพยาบาลที่ออกเลขนั้น ถ้าไม่ทราบก็ข้ามได้
- **เบอร์โทรอ่านง่ายขึ้น:** ช่องเบอร์โทรจัดรูปแบบเป็น `081-xxx-xxxx` ให้เองขณะพิมพ์ และช่องรหัสนักศึกษามีตัวอย่าง `6921xxxxx`
- **บัญชีเดิมยังใช้ได้ตามปกติ:** คนที่ชื่อแยกได้ชัดเจน (สองคำ) ระบบแยกให้เองและไม่ต้องทำอะไร คนที่ระบบแยกไม่ได้ (ชื่อคำเดียว สามคำขึ้นไป หรือชื่อเป็นตัวอักษรอังกฤษ) จะเห็นหน้าต่างให้ตรวจสอบชื่อเมื่อเข้าใช้งานครั้งถัดไป และต้องเข้าไปแก้ในหน้าโปรไฟล์

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **ฟอร์มแก้ไขนักศึกษา:** หน้า Students แก้ชื่อเป็น ชื่อ, ชื่อกลาง และนามสกุลแล้ว แทนช่องชื่อเต็มช่องเดียว และมีกติกาห้ามตัวเลขกับอักขระพิเศษเหมือนฝั่งนักศึกษา
- **Super admin ดูและแก้ผู้ติดต่อฉุกเฉินได้:** ในฟอร์มแก้ไขเดียวกัน Super admin เห็นและแก้ผู้ติดต่อฉุกเฉินของนักศึกษาได้ (ชื่อ, ชื่อกลาง, นามสกุล, ชื่อเล่น, ความสัมพันธ์, เบอร์โทร) บทบาทอื่นไม่เห็นและแก้ไม่ได้ ถ้าบันทึกไม่สำเร็จจะมีข้อความบอกสาเหตุที่ท้ายฟอร์ม
- **เลข HN:** แอดมินและ Super admin เห็น HN ในหน้าต่างข้อมูลนักศึกษา (ไอคอน i) ของรายชื่อกิจกรรม และ Super admin ดูในหน้า Medical Log และแก้ในฟอร์มแก้ไขได้ ประธานชมรมและประธานสาขาเห็น HN ในรายชื่อสมาชิกของชมรมหรือสาขาตัวเอง และในรายชื่อของกิจกรรมที่ชมรมหรือสาขาตัวเองเป็นเจ้าของ
- **ชื่อเล่นผู้ติดต่อฉุกเฉิน:** แอดมินเห็นชื่อเล่นของผู้ติดต่อฉุกเฉินในหน้าต่างข้อมูลและในไฟล์ส่งออก ส่วนประธานชมรมและประธานสาขาไม่เห็นชื่อและชื่อเล่นของผู้ติดต่อเหมือนเดิม เห็นเฉพาะความสัมพันธ์กับเบอร์โทร
- **ไฟล์ Excel ที่ส่งออก:** ไฟล์รายชื่อของกิจกรรม ชมรม และสาขา มีคอลัมน์ "Hospital Number (HN)" และ "HN Hospital" เพิ่มขึ้น (ฝั่งกิจกรรมแสดงเฉพาะแอดมินและประธานของกิจกรรมนั้น) และผู้ติดต่อฉุกเฉินไม่ได้อยู่ในช่องเดียวแบบ `Father: 081...; Mother: 089...` อีกแล้ว แต่แยกเป็นคอลัมน์ ชื่อ (ไม่มีในไฟล์ของประธาน), ชื่อเล่น (เฉพาะแอดมิน), ความสัมพันธ์ และเบอร์โทร ต่อผู้ติดต่อแต่ละคน ความสัมพันธ์แสดงเป็น "บิดา (Father)" และเบอร์โทรเป็นรูปแบบ `081-234-5678`

## ฝั่งทีม (technical changelog)

- **DB / migration:** เพิ่มคอลัมน์ใน `users` ได้แก่ `first_name`, `middle_name`, `last_name`, `latin_name_confirmed`, `name_needs_review`, `hospital_number` และ `hospital_name` ผ่าน `src/db/migrate.ts` ขั้นที่ 107 และ 108 (ตรงกับ drizzle `0055` และ `0056`) ทุกขั้นเพิ่มอย่างเดียว รันซ้ำได้ และไม่ลบข้อมูล ส่วน `users.name` ยังเป็นชื่อที่ใช้แสดงผลและถูกสร้างใหม่จากชื่อที่แยกทุกครั้งที่บันทึก ทำให้โค้ดเดิมที่อ่าน `name` ยังใช้ได้ (รันบน prod ก่อน deploy แล้ว)
- **Backfill ชื่อเดิม:** เฉพาะโปรไฟล์ที่กรอกเสร็จแล้ว ชื่อสองคำแยกเป็นชื่อกับนามสกุลโดยอัตโนมัติ ที่เหลือ (คำเดียว สามคำขึ้นไป และชื่อที่มีตัวอักษรอังกฤษ) ตั้ง `name_needs_review = true` ไม่เดาชื่อกลางและไม่แก้ `name` ผลบน prod คือ 356 คนถูก flag และ 560 คนไม่ถูก flag
- **กติกาชื่อ:** logic อยู่ใน `src/lib/profile/name.ts` (ชื่อต้องเป็นตัวอักษรทุกภาษากับเครื่องหมายผสม ช่องว่าง `-` `.` `'` เท่านั้น, ภาษาไทยเว้นแต่ยืนยัน Latin, ผู้ติดต่อฉุกเฉินใช้กติกาเดียวกันรายคนผ่าน `latinNameConfirmed` ใน jsonb) บังคับทั้งฝั่งฟอร์มและ `POST/PATCH /api/profile` และเช็ก `PATCH /api/admin/users/[id]` เฉพาะตอนชื่อเปลี่ยน เพื่อไม่ให้บัญชีเก่าที่ชื่อมีตัวเลขแก้ role ไม่ได้
- **Review prompt:** `shouldShowProfileReview` ถามทันทีเมื่อ `nameNeedsReview` เป็นจริง ซ่อนปุ่ม Keep และ `stampProfileReviewed` ปฏิเสธการยืนยันชื่อที่ถูก flag
- **PDPA / HN:** HN ถือเป็นข้อมูลทางการแพทย์ระดับรายละเอียด (ไม่นับเป็นสัญญาณว่ามีโรค) การแก้ไขของเจ้าของข้อมูลถูกบันทึกใน audit log ด้วยชื่อ field เท่านั้น การอ่านผ่านรายชื่อกิจกรรมจำกัดที่ `includeMedicalColumns` และ allow-list ของ registration/organizer/smo ยังตัด HN ออก ไม่ส่งไปที่ Songsue sync
- **สิทธิ์การเข้าถึง:** การแก้ผู้ติดต่อฉุกเฉินใน `PATCH /api/admin/users/[id]` จำกัดเฉพาะ `super_admin` และถูกละเลยสำหรับบทบาทอื่น โหลดผ่านทางอ่านที่ถูก audit ของ `GET /api/admin/students/[id]` ไม่อยู่ใน list จำนวนมาก ตรวจความถูกต้องฝั่งเซิร์ฟเวอร์ด้วย `sanitizeAdminContacts` และ audit log บันทึกชื่อ field `emergencyContacts` โดยไม่ใส่ค่า ผู้ติดต่อที่เป็นตัวอักษรอังกฤษที่แอดมินบันทึกจะถูกตั้ง `latinNameConfirmed` เพื่อไม่ให้นักศึกษาถูกบังคับพิมพ์ใหม่
- **Export:** `emergencyContactColumns` ใน `src/lib/pdpa/emergency-contacts.ts` สร้างคอลัมน์ผู้ติดต่อฉุกเฉินที่ใช้ร่วมกันทั้งสามไฟล์ ระดับประธานไม่มีคอลัมน์ชื่อและชื่อเล่น Songsue sync ส่งเฉพาะ name, relationship, phone
- **UI:** คอมโพเนนต์ร่วม `NameFields`, `ContactNameFields`, `ContactThaiNotice`, `HospitalNumberFields` และตัวช่วยเบอร์โทร `src/lib/profile/phone.ts` รวมถึง `ContactsEditor` ที่อยู่ใต้ `src/app/admin/students/_components/`
- **ตรวจสอบแล้ว:** `npm run build`, `npm run lint` (0 error) และ `vitest` 505 tests ผ่าน ทดสอบกับ Postgres จริงบนเครื่อง ทั้ง API ของนักศึกษา แอดมิน การส่งออก Excel ของกิจกรรมและชมรม สิทธิ์ของประธานชมรม และการรันซ้ำของ migration ไม่มีการทดสอบบน prod นอกจากการรัน migration และการนับจำนวนที่ถูก flag
