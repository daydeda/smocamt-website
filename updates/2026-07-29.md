## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **ชื่อบ้าน (House) แสดงถูกต้องขึ้นทุกที่ที่เคยโชว์** — หน้ารายชื่ออุทธรณ์ (Appeals), รายชื่อสมาชิกชมรม, รายชื่อทีมสาขา และไฟล์ export xlsx ตอนนี้ดึงชื่อบ้านจากสี/รหัสบ้านโดยตรง แทนที่จะเชื่อค่าที่เก็บในฐานข้อมูล ซึ่งอาจเพี้ยนได้ถ้ามีการ reseed
- **ไฟล์ export รายชื่อผู้เข้าร่วมกิจกรรม (attendance export) ของ super_admin/admin/ประธานชมรม-สาขา มีสรุปภาพรวมข้อมูลสุขภาพต่อท้ายด้วยแล้ว** (นับจำนวนต่อหมวดหมู่ ไม่ระบุชื่อ) — เดิมมีให้แค่ฝ่ายทะเบียน/ผู้จัดกิจกรรมเท่านั้น ทั้งที่กลุ่มนี้เห็นข้อมูลสุขภาพรายบุคคลอยู่แล้วในชีตหลัก

## ฝั่งทีม (technical changelog)

### รื้อโมเดล "บ้านหลายคณะ" (four-faculty-houses) ที่ใส่มาโดยไม่ตั้งใจ + เพิ่ม canonicalHouseName + ขยายสรุปข้อมูลสุขภาพใน export (PR #205)

- **Houses:** ActiveCAMT เป็นระบบของคณะ CAMT คณะเดียว — โมเดล MASSCOM/ARCH/ARTS × 4 สี (12 house rows) เป็นงานเตรียมของโปรเจกต์ Songsue ที่หลุดเข้ามาใน repo นี้โดยผิดพลาด รื้อออกทั้งหมด: ลบ `drizzle/0020-0022`, ลบขั้นตอนใน `migrate.ts` ที่ insert 12 house rows แล้วมาลบทิ้งซ้ำทุกครั้งที่ deploy (non-destructive — ไม่มี DROP/DELETE กับข้อมูลจริง มีแต่ลบ orphan rows ที่ไม่ถูกอ้างอิง)
- เพิ่ม `canonicalHouseName()` ใน `src/lib/faculties.ts` — ให้ xlsx export และหน้าจอ admin ที่ยังไม่ทำ i18n เต็ม ดึงชื่อบ้านจาก house id/colorGroup แทนคอลัมน์ `houses.name` ที่เก็บไว้ ซึ่งอาจไม่ sync กับ `seed.ts` ถ้ามีการแก้ไขระหว่างรอบ reseed
- **PDPA:** ขยาย aggregate medical summary block ใน `api/admin/events/[id]/export` ให้ครอบคลุม admin/super_admin/ประธานชมรม-สาขา ด้วย (เดิมมีให้แค่ฝ่ายทะเบียน/ผู้จัดกิจกรรม) — กลุ่มนี้เห็นข้อมูลสุขภาพรายบุคคลอยู่แล้วในชีตหลัก การเห็นสรุปเพิ่มจึงไม่ใช่สิทธิ์ใหม่ ส่วนการซ่อนสรุปเมื่อผู้เข้าร่วมน้อยกว่า 5 คน (กันเดาตัวบุคคล) ยังคงใช้เฉพาะกลุ่มฝ่ายทะเบียน/ผู้จัดกิจกรรมเหมือนเดิม
- ตรวจสอบด้วย `npm run lint`, `npm run build` (ผ่านทั้งคู่ ไม่มี error ใหม่)
- ตัดแพ็กเกจนี้เป็น **tag/release v1.12.1**
