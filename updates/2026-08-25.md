## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **หน้า "ตรวจสอบคำสั่งซื้อร้านค้า" (`/admin/shop`) มีปุ่ม "ต้องตรวจสอบ" ใหม่** ระบบจะเช็กสลิปโอนเงินของทุกคำสั่งซื้อให้อัตโนมัติและฟรี โดยดูว่ารูปสลิปซ้ำกับคำสั่งซื้ออื่นไหม หรือ QR บนสลิปซ้ำกับที่เคยใช้มาก่อนไหม (แม้จะถ่ายรูปมาใหม่ ครอปหรือบีบไฟล์ต่างกัน) หรือสลิปนั้นไม่มี QR ให้อ่านเลย คำสั่งซื้อที่เข้าข่ายจะขึ้นป้ายเตือนสีเหลืองหรือแดงพร้อมเหตุผลเป็นภาษาไทยตรงบนการ์ดคำสั่งซื้อ กดปุ่ม "ต้องตรวจสอบ" มุมบนจะกรองให้เห็นเฉพาะคำสั่งซื้อที่ต้องดูจริง ๆ ไม่ต้องไล่เปิดทีละใบ
- **ปุ่ม "ยืนยันกับธนาคาร" บนการ์ดคำสั่งซื้อ** ถ้าสลิปมี QR ที่อ่านได้ ระบบจะแปลงเป็นลิงก์ไปหน้ายืนยันสลิปของธนาคารเจ้าของ QR นั้นให้เลย แอดมินกดเปิดดูได้เลยจากในหน้าเดียวกัน ไม่ต้องหยิบมือถือมาสแกนรูปสลิปซ้ำอีกรอบ
- ทั้งหมดนี้ทำงานแบบออฟไลน์บนเซิร์ฟเวอร์เราเอง ไม่ได้เรียกใช้บริการตรวจสลิปแบบเสียเงินรายเดือน (เช่น EasySlip/SlipOK) เพราะปริมาณคำสั่งซื้อต่อเดือนของร้านยังไม่คุ้มกับค่าบริการ

## ฝั่งทีม (technical changelog)

### สลิปตรวจสอบอัตโนมัติแบบฟรีสำหรับร้านค้า (PR #223)

- **DB/migration:** เพิ่มคอลัมน์ nullable ใหม่ 3 ตัวในตาราง `shop_orders` คือ `slip_hash`, `slip_qr_payload`, `slip_flag` พร้อม index สำหรับค้นหาซ้ำ (`drizzle/0035_spotty_nuke.sql`) ยัง **ไม่ได้รันบน prod** ต้องรัน `npm run db:migrate:container` จาก Portainer console ก่อน deploy โค้ดรอบนี้ (ดู `/safe-deploy`)
- **โมดูลใหม่ `src/lib/shop-slip-verify.ts`:** แฮช sha256 ของรูปสลิป และถอดรหัส QR ในรูปด้วย `sharp` + `jsqr` (dependency ใหม่ ทำงานออฟไลน์ทั้งคู่) แล้วเทียบกับสลิปของคำสั่งซื้ออื่นที่ยังไม่ถูกปฏิเสธ เพื่อ flag `duplicate_image` / `duplicate_qr` / `no_qr` มี unit test คลุม 17 เคส
- `POST /api/shop/orders` คำนวณ flag ก่อนเริ่ม transaction ล็อก stock เพื่อไม่ให้งาน I/O และถอดรหัส QR ไปถือ row lock ค้างไว้
- `GET /api/admin/shop/orders` ส่ง `slipFlag`/`slipQrPayload` เพิ่มให้ `AdminShopClient.tsx` แสดงป้ายเตือนและลิงก์ยืนยันธนาคารตามที่อธิบายด้านบน
- **Perf follow-up ในพีอาร์เดียวกัน:** ย้ายจุดคำนวณแฮช/QR จากตอนสร้างคำสั่งซื้อ (ต้องดาวน์โหลดรูปสลิปกลับมาจาก storage ใหม่ทุกครั้ง) ไปทำตอนอัปโหลดสลิปแทน (`POST /api/shop/slip`) ตอนที่ไฟล์ยังอยู่ใน memory อยู่แล้ว แล้วเซ็น HMAC ผลลัพธ์ส่งต่อผ่าน client ให้ตอนสร้างคำสั่งซื้อแค่ตรวจลายเซ็น ไม่ต้องดาวน์โหลดรูปซ้ำ ถ้า token หายหรือหมดอายุระบบจะ fallback ไปดาวน์โหลดคำนวณใหม่แบบเดิมโดยอัตโนมัติ ไม่ทำให้สั่งซื้อล้มเหลว
- **สิทธิ์เข้าถึง/PDPA:** ไม่กระทบ gate หรือ audit log เดิม เพราะเป็น metadata เพิ่มเติมของสลิปที่มีอยู่แล้ว การเปิดดูสลิปยังคง audit log เหมือนเดิมทุกจุด
- ตรวจสอบแล้วด้วย `npm test` (161 ผ่านทั้งหมด), `npm run lint`, และ `npm run build` ไม่พบ error ใหม่จากไฟล์ที่แก้ในรอบนี้
