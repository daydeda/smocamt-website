## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **ประธานชมรมและประธานสาขาเข้าหน้า "จัดการร้านค้า" (`/admin/shop`) ได้แล้ว แบบเห็นเฉพาะของตัวเอง** เดิมร้านค้าเป็นร้านกลางร้านเดียวที่มีแต่ super_admin กับ admin จัดการได้ ตอนนี้สินค้าแต่ละชิ้นมี "เจ้าของ" เป็นชมรมหรือสาขาได้ ประธานที่ล็อกอินเข้ามาจะเห็นแค่สินค้าและคำสั่งซื้อของชมรมหรือสาขาที่ตัวเองดูแล ไม่เห็นของทีมอื่น และไม่เห็นสลิปโอนเงินของคำสั่งซื้อที่ไม่ใช่ของตัวเอง
- **ตอนสร้างหรือแก้สินค้ามีช่องเลือกเจ้าของ (ชมรม/สาขา) เพิ่มเข้ามา** ประธานจะเลือกได้เฉพาะชมรมหรือสาขาที่ตัวเองเป็นประธาน ส่วน admin เลือกได้ทุกอัน หรือเว้นว่างไว้ให้เป็น "สินค้าส่วนกลาง (SMO)" ที่มีแต่ admin จัดการได้เหมือนเดิม สินค้าเดิมทุกชิ้นถือเป็นสินค้าส่วนกลางไปก่อน จนกว่า admin จะไปกำหนดเจ้าของให้
- **การอนุมัติหรือปฏิเสธคำสั่งซื้อของประธานจำกัดเฉพาะออเดอร์ที่เป็นของตัวเองล้วน ๆ** ถ้าออเดอร์หนึ่งมีสินค้าของหลายทีมปนกัน ประธานจะเห็นแบบอ่านอย่างเดียว และให้แอดมินร้าน (SMO) เป็นคนตรวจ เพราะการกดอนุมัติหรือปฏิเสธมีผลกับทั้งออเดอร์และสต็อกทั้งก้อน
- **การตั้งค่าร้าน (QR ข้อมูลการชำระเงิน ค่าจัดส่ง) ยังเป็นของ admin เท่านั้น** แท็บ "ตั้งค่า" จะไม่ขึ้นให้ประธานเห็น

## ฝั่งทีม (technical changelog)

### ร้านค้าแยก scope ตามประธานชมรม/สาขา (PR #224)

- **DB/migration:** เพิ่มคอลัมน์ nullable ใหม่ 2 ตัวในตาราง `shop_products` คือ `owner_club_ids` กับ `owner_majors` (jsonb) เลียนแบบ pattern ของ `events.owner_club_ids` / `owner_majors` ทั้งคู่ว่าง = สินค้าส่วนกลาง (super_admin/admin เท่านั้น) migration เป็น `ADD COLUMN IF NOT EXISTS` แบบ idempotent ไม่ทำลายข้อมูล (`drizzle/0036_groovy_eddie_brock.sql`) แถวเดิมทั้งหมดยังเป็นสินค้าส่วนกลาง ยัง **ไม่ได้รันบน prod** ต้องรัน `npm run db:migrate:container` จาก Portainer console ก่อน redeploy รอบนี้ (ดู `/safe-deploy`)
- **สิทธิ์เข้าถึง (4 layer):** `isShopAdmin` (super_admin/admin) ยังเป็น gate แบบไม่จำกัด scope เหมือนเดิม เพิ่ม `isShopManager` ที่รวม `club_president` / `major_president` เข้ามาเป็น gate "เข้าหน้าจัดการร้านได้ไหม" เพิ่ม `/admin/shop` เข้า `SCANNER_ONLY_PAGES` ใน `admin-access.ts` และ branch ใน `admin-nav-config.ts` ให้ proxy กับเมนูปล่อยประธานผ่าน หน้า `page.tsx` เปลี่ยน gate เป็น `isShopManager` (smo ยังโดนเด้งออก)
- **โมดูลใหม่ `src/lib/shop-scope.ts`:** `resolveShopAccess(session)` คืน `{ unscoped }` หรือ `{ unscoped: false, scope }` โดย reuse `EventScopeService.getPresidentScope` และ `classifyOrdersByScope` เช็กว่าแต่ละ order มีรายการที่ประธานเป็นเจ้าของกี่รายการ (มีบางส่วน / ครบทุกรายการ) ส่วน predicate บริสุทธิ์ `isProductOwnedByScope` / `filterProductsByScope` / `isOwnerAssignmentWithinScope` อยู่ใน `shop-auth.ts` มี unit test คลุม 12 เคสใน `shop-auth.test.ts`
- **Route ฝั่ง server ตรวจ scope เองทุกจุด ไม่พึ่ง UI:** `GET /api/admin/shop/products` กรองเหลือเฉพาะสินค้าที่เป็นเจ้าของ และเปลี่ยน response เป็น `{ products, scoped, ownerOptions }` การสร้าง/แก้/ลบ/export ปฏิเสธสินค้าที่อยู่นอก scope และห้ามประธานสร้างสินค้าส่วนกลางหรือย้ายเจ้าของออกนอก scope ตัวเอง `GET /api/admin/shop/orders` คืนเฉพาะออเดอร์ที่มีรายการของตัวเอง ตัดรายการของทีมอื่นออกจาก response และเพิ่มฟิลด์ `fullyInScope` `PATCH /api/admin/shop/orders/[id]` กับ `GET /api/shop/orders/[id]/slip` ต้องเป็นออเดอร์ที่ทุกรายการเป็นของประธานคนนั้น ไม่งั้นตอบ 403 route ตั้งค่าร้านยังเป็น `isShopAdmin` เพิ่ม `GET /api/admin/shop/context` ใหม่ให้ client รู้ว่าตัวเอง scoped หรือไม่
- **PDPA/audit:** การที่ประธานเห็นชื่อ เบอร์ ที่อยู่จัดส่งของผู้ซื้อ ยังเขียน audit log ทุกครั้งเหมือน queue เดิม (ข้อความ log ระบุว่าเป็น scoped view) กลไกความรับผิดชอบของสิทธิ์ที่กว้างขึ้นนี้คือ audit log เหมือน tier ประธานชมรม/สาขาเรื่องข้อมูลการแพทย์ใน `CLAUDE.md` ไม่มีการอ่านข้อมูลการแพทย์เพิ่มในรอบนี้
- **UI (`AdminShopClient.tsx`):** เพิ่มตัวเลือกเจ้าของ (ชมรม/สาขา) ในฟอร์มสินค้า มีป้ายบอกเจ้าของบนแถวรายการสินค้า ซ่อนแท็บ "ตั้งค่า" สำหรับประธาน และซ่อนปุ่มอนุมัติ/ปฏิเสธกับสลิปบนออเดอร์ที่ปนหลายทีม พร้อมข้อความว่าให้แอดมินร้านเป็นคนตรวจ
- ตรวจสอบแล้วด้วย `npm test` (174 ผ่านทั้งหมด), `npm run lint`, และ `npm run build` ไม่พบ error ใหม่จากไฟล์ที่แก้ในรอบนี้ ยังไม่ได้ซ้อม migration บน local กับ `/verify` เพราะ Docker ไม่ได้รันตอนพัฒนา ต้องทำก่อน deploy จริง
