## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **หน้าโปรไฟล์/การกรอกข้อมูลครั้งแรก (onboarding) ตรวจคณะให้อัตโนมัติจากรหัสนักศึกษา** — เดิมต้องเลือกคณะเอง (แม้ ActiveCAMT จะรองรับเฉพาะ CAMT) พอกรอกรหัสนักศึกษาครบ 9 หลัก ระบบจะอ่านคณะจากตัวเลขในรหัสให้ทันที ถ้ารหัสไม่ตรงกับ CAMT จะมีข้อความแจ้งเตือนให้ตรวจสอบรหัสนักศึกษาอีกครั้งหรือติดต่อเจ้าหน้าที่ ป้องกันการพิมพ์รหัสผิดตั้งแต่ต้นทาง
- **ฟีเจอร์ใหม่สำหรับสตาฟ: ปุ่ม "นับรวมกับ Songsue ด้วย" ในหน้าแก้ไขกิจกรรม** — กิจกรรมที่ติ๊กเลือกไว้ จะส่งข้อมูลกิจกรรมและสถานะการลงทะเบียน/เข้าร่วมของนักศึกษาแต่ละคนไปให้แอป Songsue (แอปพี่น้องของ ActiveCAMT) ด้วย เพื่อให้ Songsue นับคะแนนบ้านฝั่งของตัวเองได้ถูกต้อง — เป็นการส่งข้อมูลทางเดียว ActiveCAMT ยังเป็นเจ้าของข้อมูลกิจกรรม/การลงทะเบียน/เช็คอินเหมือนเดิมทุกอย่าง และไม่มีการส่งข้อมูลสุขภาพหรือผู้ติดต่อฉุกเฉินไปด้วย

## ฝั่งทีม (technical changelog)

### ฟีเจอร์ใหม่: Songsue event sync flag + ตรวจคณะจากรหัสนักศึกษา (PR #194)

- **schema:** เพิ่ม `events.songsueLinked` (boolean, `NOT NULL DEFAULT false`) — migration แบบ additive/idempotent (`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`) ไม่มีขั้นตอนทำลายข้อมูล
- **`src/lib/songsue-sync.ts`** (ใหม่) — best-effort, one-directional sync ไปยังแอป Songsue ผ่าน service-to-service route 2 ตัว (`/api/integrations/activecamt/events`, `/api/integrations/activecamt/register`) ยืนยันตัวตนด้วย shared secret (`ACTIVECAMT_SYNC_SECRET`) **ไม่ throw ทุกกรณี** — error ถูก log (`captureException`) แล้วกลืนไว้เสมอ เพื่อไม่ให้ Songsue ล่มแล้วไปบล็อกการบันทึกกิจกรรม/ลงทะเบียน/เช็คอินฝั่ง ActiveCAMT
- จุดเรียก sync: `POST/PUT /api/admin/events` (สร้าง/แก้ไขกิจกรรม — เฉพาะตอนแก้ live column จริง ไม่ใช่ตอนเก็บ pending diff ของประธานชมรม/สาขาหรือตอน discard), `POST/DELETE /api/events/[id]/register` (ลงทะเบียน/ยกเลิก), และ `ScannerService` (เช็คอินสำเร็จทุก path)
- **PDPA:** ส่งเฉพาะ identity field ที่จำเป็นสำหรับสร้างบัญชี Songsue ขั้นต่ำ (email/studentId/name/prefix/faculty/major/phone) — ไม่ส่งข้อมูลสุขภาพ ผู้ติดต่อฉุกเฉิน หรือสถานะ PDPA consent ใด ๆ
- เพิ่ม env var ใหม่ `SONGSUE_SYNC_URL`, `ACTIVECAMT_SYNC_SECRET` ใน `docker-compose.yml`/`docker-stack.yml` — ทั้งสองตัว optional, sync จะ no-op เงียบ ๆ ถ้าไม่ได้ตั้งค่า
- **`src/lib/faculties.ts`:** เพิ่ม `facultyFromStudentId` อ่านรหัสคณะ (หลักที่ 3-4 ของรหัสนักศึกษา, code `21` = CAMT ตาม km-core-62213.pdf) แทนการเชื่อค่าที่ผู้ใช้เลือกเอง — ใช้ในหน้า profile และ onboarding เป็น typo protection
- i18n ครบ 4 ภาษา (EN/TH/MM/CN) สำหรับ label/hint ของปุ่ม Songsue toggle
- ตรวจสอบด้วย `npm run lint`, `npm run build` (ผ่านทั้งหมด — error เดิมใน `battle-flow.test.ts` ไม่เกี่ยวข้องกับแพ็กเกจนี้)
- ตัดแพ็กเกจนี้เป็น **tag/release v1.9.0**
- **⚠️ Prod ยังไม่ migrate ณ ตอน tag release นี้** — ต้องรัน `npm run db:migrate:container` ผ่าน Portainer console (`activecamt-app`) ก่อน deploy code เวอร์ชันนี้

### แก้ CI: fixture ทดสอบเกม (battle/OX) ขาดคอลัมน์ตำแหน่งงานที่แยกตาม major/SMO/ANUSMO (PR #195)

- `stats-helper.test.ts` และ `battle-flow.test.ts` สร้างตาราง `users` แบบ raw SQL จำลองไว้ทดสอบ (ไม่ได้ migrate จาก schema จริง) — ตารางจำลองนี้เขียนไว้ก่อน PR #192 เพิ่ม `major_position`/`smo_position`/`anusmo_position` จึงขาด 3 คอลัมน์นี้ไป ทำให้ CI พังด้วย `column "major_position" of relation "users" does not exist` (ผ่านตอนรันในเครื่องเพราะทดสอบกับ Postgres จริงที่ migrate แล้ว)
- เพิ่ม 3 คอลัมน์เข้าไปในตาราง fixture ทั้งสองไฟล์ให้ตรงกับ `schema.ts` — ไม่แตะโค้ด runtime หรือ schema จริง ผลคือ CI ทั้ง 111 เทสต์ผ่าน
- ตัดแพ็กเกจนี้เป็น **tag/release v1.9.1**
