# อัปเดต ActiveCAMT ประจำวันที่ 23 ต.ค. 69

สรุปสำหรับวันที่ 23 ต.ค. 69 เอาไว้ลง Discord และให้ทีมที่เกี่ยวข้องอ่านกัน

---

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **หน้ากิจกรรมแบบสาธารณะ:** ลิงก์กิจกรรมที่แชร์ไปใน LINE หรือ Discord จะแสดงโปสเตอร์ วันเวลา สถานที่ และที่นั่งที่จองแล้ว โดยไม่ต้องเข้าสู่ระบบก่อน
- **ผู้เยี่ยมชมที่ยังไม่ได้เข้าสู่ระบบ** ดูอันดับบ้าน ปฏิทินกิจกรรม และร้านค้าได้ ส่วนการลงทะเบียน การสั่งซื้อ และอันดับรายบุคคลยังต้องเข้าสู่ระบบก่อน
- **ปฏิทิน:** ผู้ที่ยังไม่ได้เข้าสู่ระบบสามารถติดตามปฏิทินกิจกรรมผ่าน Google Calendar หรือ Apple Calendar ได้ด้วยลิงก์สาธารณะ
- **หน้าแรก:** ผู้เข้าชมใหม่เห็นกิจกรรมที่กำลังจะมาถึง อันดับบ้าน และประกาศล่าสุดก่อนเข้าสู่ระบบ

- ไม่มีการเปลี่ยนแปลงหน้าจัดการสำหรับทีมงานในรอบนี้

---

## ฝั่งทีม (technical changelog)

- **Public routes:** เพิ่ม `/e/<id>` (ผ่าน `EventsService.getPublicEvent`, ใช้ `isEligibleForGuest` และคืน 404 สำหรับกิจกรรมที่ไม่เปิดให้ผู้เยี่ยมชม) และหน้าแรก `/` สำหรับผู้ที่ยังไม่เข้าสู่ระบบ เปิด `/dashboard/houses`, `/dashboard/calendar` และ `/dashboard/shop` ให้ผู้เยี่ยมชมผ่าน `src/proxy.ts`
- **PDPA:** `/api/shop` คืนข้อมูลแบบ browse-only ให้ผู้ที่ยังไม่เข้าสู่ระบบ ไม่มีข้อมูลการชำระเงิน การจัดส่ง/รับของ หรือราคาสวัสดิการ ชื่อผู้ขายคืนเฉพาะชื่อที่แสดง อันดับรายบุคคลและฟีดกิจกรรมของบ้านยังต้องเข้าสู่ระบบ (401) เหมือนเดิม
- **ปฏิทิน:** เพิ่ม `/api/calendar/public` (.ics ไม่มี token, cache 5 นาที) และย้ายการแมปรายการปฏิทินไปไว้ `src/lib/calendar/ical.ts` (`toCalItems`) ให้ feed ส่วนตัวกับ feed สาธารณะใช้ร่วมกัน ลิงก์ของกิจกรรมใน feed ชี้ไป `/e/<id>` แล้ว
- **Access:** การเข้าถึงของผู้เยี่ยมชมทั้งหมดผ่าน `isEligibleForGuest` และใช้ข้อมูลเฉพาะที่ไม่ระบุตัวนักศึกษา
- **ไม่มีการเปลี่ยน DB schema หรือ migration** (ไม่ต้องรัน `db:migrate:container` ก่อน deploy)
- **ตรวจสอบแล้ว:** `npm run build`, `tsc`, `npm run lint` (ไม่มี error ใหม่) และ `vitest` 430 tests ผ่าน

# ActiveCAMT v2.31.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **แจ้งเตือนก่อนแบบฟอร์มปิด:** ถ้ามีแบบทดสอบ แบบประเมินทัศนคติ หรือแบบประเมินความคิดเห็นที่ยังไม่ได้ทำ ระบบจะส่ง push เตือนก่อนปิด 24 ชั่วโมง และอีกครั้งเมื่อเหลือ 1 ชั่วโมง ผู้ที่ส่งแบบฟอร์มไปแล้วจะไม่ได้รับการแจ้งเตือน
- **กิจกรรมใหม่ให้ลงทะเบียน:** เมื่อทีมงานเปิดกิจกรรมใหม่ นักศึกษาที่เข้าร่วมได้จะได้รับ push แจ้งว่าลงทะเบียนได้แล้ว

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **หน้าโปรไฟล์:** ปุ่มทดสอบการแจ้งเตือนมีตัวอย่างใหม่สามแบบ ได้แก่ แบบฟอร์มใกล้ปิด 24 ชั่วโมง แบบฟอร์มใกล้ปิด 1 ชั่วโมง และกิจกรรมใหม่ ระบบจะส่งให้อุปกรณ์ของผู้ทดสอบเท่านั้น

## ฝั่งทีม (technical changelog)

- **Push:** เพิ่ม `ReminderService.runFormReminders` และ `GET /api/cron/reminders` (ตรวจ `CRON_SECRET` แบบ fail-closed) โดย scheduler เรียกทุก 5 นาที ผู้รับใช้กฎเดียวกับแบนเนอร์แบบฟอร์มที่ยังไม่ได้ทำ
- **Push กิจกรรมใหม่:** `getNewEventAudienceUserIds` ใช้ `isEligibleFor` โดยไม่ข้าม admin bypass และส่งหลัง response ผ่าน `after()` ไม่ส่งให้กิจกรรม walk-in-only หรือกิจกรรมที่เริ่มแล้ว
- **DB/migration:** migration step 104 และ `drizzle/0052_first_havok.sql` สร้างตาราง `form_reminders` (form_id, stage) พร้อม unique index เพื่อกันการส่งซ้ำ เพิ่มแบบ idempotent และไม่ทำลายข้อมูล รันบน prod แล้วก่อนปล่อยโค้ด
- **Scheduler:** `scripts/cron-runner.mjs` เพิ่ม job `/api/cron/reminders` ทุก 5 นาที
- **การเข้าถึง/PDPA:** ไม่มีการอ่านข้อมูลทางการแพทย์ใหม่ และไม่มีการเปลี่ยนสิทธิ์การเข้าถึง

อัปเดตรอบนี้รวม commit `31018dc` (feat(push): form-closing reminders and new-event pushes) และ release v2.31.0

# ActiveCAMT v2.32.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **ชวนเพิ่มแอปไว้บนหน้าจอโฮมและเปิดการแจ้งเตือน:** หลังเข้าสู่ระบบและกรอกโปรไฟล์ครบ ทุกหน้าของแอปจะมีหน้าต่างชวนให้เพิ่ม ActiveCAMT ไว้บนหน้าจอโฮมและเปิดการแจ้งเตือน เพื่อให้ได้รับการแจ้งเตือนใหม่ทั้งหมด เช่น เตือนก่อนแบบทดสอบหรือแบบประเมินปิด กิจกรรมใหม่ และที่นั่งจากคิวรอ หน้าต่างนี้ขึ้นทันทีที่เข้าหน้า วางอยู่เหนือหน้าต่างอื่น และอยู่จนกว่าผู้ใช้จะกดปุ่ม ยกเว้นหน้าสแกน
- **บน iPhone และ iPad** มีภาพสอน 4 ขั้นตอนตามหน้าจอ Safari จริง แตะไอคอนสองขีดข้างแถบที่อยู่เว็บ เลือกแชร์ เลือกเพิ่มไปยังหน้าจอโฮม แล้วเปิดแอปจากหน้าจอโฮมเพื่อเปิดการแจ้งเตือน เพราะ iPhone ส่งการแจ้งเตือนได้เฉพาะแอปที่เพิ่มไว้บนหน้าจอโฮม ระบบแยก iPad ออกจาก Mac ได้แม้ iPad จะส่งตัวตนแบบ Mac
- **บน Android (มือถือและแท็บเล็ต) และคอมพิวเตอร์** มีปุ่มติดตั้งแอปและปุ่มเปิดการแจ้งเตือนกดได้ทันที ถ้าเปิดลิงก์จาก LINE, Facebook หรือ Instagram ระบบจะบอกให้เปิดใน Safari หรือ Chrome ก่อน และถ้าเคยบล็อกการแจ้งเตือนไว้ จะบอกวิธีเปิดกลับในการตั้งค่า
- กด "ไว้ทีหลัง" แล้วจะไม่ถามอีก 3 วัน ตั้งแต่ครั้งที่สามจะมีตัวเลือก "ไม่ต้องถามอีก" ซึ่งเว้นไป 14 วัน เมื่อเปิดการแจ้งเตือนแล้วจะไม่เห็นหน้าต่างนี้อีกบนอุปกรณ์นั้น รองรับทั้ง 4 ภาษาและโหมดมืด
- **หน้าโปรไฟล์:** การ์ดการแจ้งเตือนมีกรอบและระยะห่างเหมือนส่วนอื่น (เดิมติดกับส่วนถัดไป) คำอธิบายบอกครบว่าจะได้รับอะไร และบน iPhone ที่ยังไม่ได้เพิ่มแอป การ์ดจะบอกวิธีเพิ่มแทนที่จะหายไป
- **แจ้งเตือนเมื่อเจ้าหน้าที่ตอบกลับข้อเสนอแนะ/ข้อร้องเรียน:** หน้าส่งความคิดเห็นมีช่องให้ติ๊ก "แจ้งเตือนฉันเมื่อเจ้าหน้าที่ตอบกลับ" (ไม่บังคับ และปิดไว้เป็นค่าเริ่มต้น) เมื่อเจ้าหน้าที่ตอบกลับหรือตั้งสถานะว่าดำเนินการแล้ว ผู้ที่ติ๊กไว้จะได้ push ที่บอกเพียงว่ามีความคืบหน้า ไม่แสดงเนื้อหา ผู้ที่ไม่ติ๊กยังไม่ระบุตัวตนเหมือนเดิม

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- ทีมงานทุกบทบาทเห็นหน้าต่างชวนเพิ่มแอปเหมือนนักศึกษา แต่จะไม่ขึ้นในหน้าสแกน จึงไม่รบกวนตอนสแกนเช็กอิน
- **ปุ่มทดสอบการแจ้งเตือนในหน้าโปรไฟล์ของแอดมิน** มีตัวอย่างใหม่สองแบบ คือ "ข้อเสนอแนะ: เจ้าหน้าที่ตอบกลับ" และ "ข้อเสนอแนะ: ดำเนินการแล้ว" ส่งเฉพาะไปยังอุปกรณ์ของผู้ทดสอบ
- เจ้าหน้าที่ยังไม่เห็นว่าใครเป็นผู้ส่งข้อเสนอแนะ แม้ผู้ส่งจะเลือกรับการแจ้งเตือน

## ฝั่งทีม (technical changelog)

- **PWA/Push:** เพิ่ม `InstallPushPrompt` ใน root layout (`src/app/layout.tsx`) และ logic แบบ pure ใน `src/lib/ui/install-prompt.ts` (`pickInstallScreen` เลือกหน้าจอจาก user agent, standalone, permission และ subscription) การเปิดการแจ้งเตือนใช้ `enablePushNotifications()` ตัวเดิม จึงขอสิทธิ์เฉพาะตอนผู้ใช้กดปุ่ม ปุ่มติดตั้งบน Android ใช้ `beforeinstallprompt` ไม่แสดงบนหน้าสแกน (`/dashboard/scan`, `/admin/scanner`) และ z-index 2100 เหนือหน้าต่างอื่น
- **อุปกรณ์:** `isIOSUserAgent` รับ `maxTouchPoints` เพื่อแยก iPad ที่ส่ง user agent แบบ Macintosh (Mac ไม่มีหน้าจอสัมผัส) ใช้ร่วมกับ `canRequestPushPermission` และ `needsIosInstall` ใหม่ ซึ่งแก้ให้การ์ดการแจ้งเตือนบนหน้าโปรไฟล์แสดงคำแนะนำบน Safari ของ iPhone แทนที่จะถูกซ่อนเพราะไม่มี `PushManager` และ `enablePushNotifications()` ตรวจ service worker ก่อน เพื่อไม่ให้ปุ่มหมุนค้างเมื่อไม่มี worker
- **Snooze:** เก็บใน `localStorage` แยกตามเครื่อง ไม่ส่งข้อมูลใหม่ไปเซิร์ฟเวอร์ ผลลัพธ์ดูได้จากจำนวนแถวใน `push_subscriptions`
- **Push ข้อเสนอแนะถึงผู้ส่ง (opt-in):** คอลัมน์ใหม่ `feedback_complaints.push_notify_user_id` (`drizzle/0054_known_quasimodo.sql`, `migrate.ts` step 106) เป็น uuid ธรรมดาไม่มี FK และตั้งค่าเฉพาะเมื่อผู้ส่งติ๊กเลือก ไม่เคยถูก select ในผลลัพธ์ฝั่งแอดมิน ส่ง push ผ่าน `notifySubmitterPush` เมื่อเจ้าหน้าที่ตอบ (`postStaffMessage`) หรือตั้งสถานะ `resolved` (`updateComplaint`) ข้อความ push เป็นข้อความทั่วไป (`src/lib/push/feedback-push.ts`) ไม่มีหมวดหรือเนื้อหา และล้างคอลัมน์เมื่อปิดเรื่อง (`closeMine` หรือ staff ตั้งเป็น `closed`) บันทึกเหตุผลและข้อแลกเปลี่ยนไว้ใน `docs/features/feedback-complaints.md` §5.2
- **DB/migration:** เพิ่มคอลัมน์แบบ idempotent และไม่ทำลายข้อมูล แถวเดิมทั้งหมดเป็น NULL ต้องรัน `db:migrate:container` บน prod ก่อน deploy
- **i18n:** เพิ่มคีย์ `installPrompt*` และ `feedbackPushOptIn*` ทั้ง EN, TH, MM และ CN
- **การเข้าถึง/PDPA:** ไม่เปลี่ยนสิทธิ์การเข้าถึงและไม่แตะข้อมูลทางการแพทย์ แต่มีข้อยกเว้นต่อหลักการไม่ระบุตัวตนของระบบข้อเสนอแนะสำหรับแถวที่ผู้ส่งเลือกรับ push เท่านั้น ควรให้ผู้รับผิดชอบด้าน PDPA รับทราบ
- **ตรวจสอบแล้ว:** `tsc`, `npm run lint` (ไม่มี error ใหม่) และ `vitest` 474 tests ผ่าน ทดสอบบนเครื่อง local ด้วยการจำลอง iPhone, iPad, Android และเบราว์เซอร์ใน LINE รวมถึงลองส่งข้อเสนอแนะแบบเลือกและไม่เลือก ตอบ ตั้งสถานะ และปิดเรื่อง แต่ยังไม่ได้ทดสอบบนอุปกรณ์จริงและยังไม่ได้ยืนยันการส่ง push จริงถึงผู้ส่ง

อัปเดตรอบนี้รวม commit `7420486` (feat(pwa): install and notifications prompt, feedback reply push) และ release v2.32.0

# ActiveCAMT v2.32.2 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- ไม่มีการเปลี่ยนแปลงที่มองเห็นได้ รอบนี้เป็นการอัปเดตความปลอดภัยของระบบเบื้องหลัง

## ฝั่งทีม (technical changelog)

- **ความปลอดภัย (dependencies):** รัน `npm audit fix` แบบไม่ breaking อัปเดต Next.js จาก 16.3.4 เป็น 16.4.3 เพื่อปิดช่องโหว่ระดับ critical (remote code execution ใน `next/og` ซึ่งแอปไม่ได้ใช้ แต่ปิดไว้ก่อน) และปิดช่องโหว่ระดับ high ใน `sharp`, `brace-expansion`, `source-map-js`, `vite` รวมถึง `vitest` ผล audit ลดจาก 17 เหลือ 10 รายการ
- **ที่ยังคงไว้:** `nodemailer` อยู่ที่เวอร์ชัน 8 เพราะ `@auth/core` รองรับแค่ 7 หรือ 8 และช่องโหว่ต้องใช้ option `raw` ซึ่งแอปไม่ได้ใช้ ส่วน `drizzle-kit`/`esbuild` เป็นเครื่องมือฝั่ง dev และ `exceljs`/`uuid` มีทางแก้เดียวคือ downgrade จึงยังไม่แตะ
- **Build:** v2.32.1 ไม่ได้ขึ้น prod เพราะ `package-lock.json` สร้างด้วย npm 11 แต่ Docker image ใช้ npm 10 ซึ่งปฏิเสธ lockfile ตอน `npm ci` รอบนี้สร้าง lockfile ใหม่ด้วย npm 10.9.9 ใช้ได้ทั้ง npm 10 และ 11 และทดสอบ `docker build` บนเครื่องผ่านก่อน push
- **หมายเหตุ:** build ของ commit changelog v2.32.0 ล้มที่ขั้นโหลดฟอนต์ Noto Sans SC จาก Google Fonts ครั้งเดียว ไม่กระทบ prod เพราะ build ของโค้ด v2.32.0 ผ่านและ deploy ไปแล้ว และ build รอบนี้โหลดฟอนต์ผ่านปกติ
- **ไม่มีการเปลี่ยน DB schema หรือ migration** และไม่แตะสิทธิ์การเข้าถึงหรือข้อมูลทางการแพทย์
- **ตรวจสอบแล้ว:** `npm run build`, `npm run lint` (ไม่มี error ใหม่), `vitest` 474 tests ผ่าน และ `docker build` บนเครื่องผ่าน

อัปเดตรอบนี้รวม commit `cf8568c` (chore(deps): security updates, Next.js 16.4.3) และ `da99a3e` (fix(deps): regenerate package-lock with npm 10 for the Docker build) โดย release v2.32.1 ไม่ได้ขึ้น prod และเนื้อหาทั้งหมดขึ้น prod ใน release v2.32.2
