## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **ล้างออร์เดอร์ทดสอบและรูปสลิปของสินค้าได้แล้ว** ที่ผ่านมาการลบสินค้าในหน้าจัดการร้านค้าจะลบแค่ตัวสินค้า ส่วนออร์เดอร์และรูปสลิปทั้งหมดยังค้างอยู่ในระบบ ตอนนี้มีสคริปต์ให้ทีมเทคนิครันจาก Portainer เพื่อลบออร์เดอร์ของสินค้าที่ระบุพร้อมสลิปของออร์เดอร์นั้นได้ในครั้งเดียว
- **เก็บกวาดรูปสลิปที่ไม่มีออร์เดอร์ได้ด้วย** รูปพวกนี้เกิดตอนผู้ซื้อเลือกรูปสลิปแล้วเปลี่ยนรูปหรือปิดหน้าสั่งซื้อไปก่อนกดยืนยัน ซึ่งเจอเยอะมากช่วงทดสอบ ระบบจะลบเฉพาะไฟล์ที่เก่ากว่า 24 ชั่วโมง คนที่กำลังสั่งซื้ออยู่จึงไม่โดนลบรูปไปกลางทาง
- ตัวแอปเองยังไม่ลบสลิปอัตโนมัติเหมือนเดิม เพราะสลิปคือหลักฐานการจ่ายเงินของออร์เดอร์จริง การลบทำได้ผ่านสคริปต์นี้เท่านั้น

## ฝั่งทีม (technical changelog)

### สคริปต์ล้างออร์เดอร์ทดสอบและสลิปกำพร้า (PR #267, merge commit `1fcc4ec`)

- **สาเหตุ:** `shop_order_items.product_id` เป็น `ON DELETE SET NULL` และเก็บ `product_name` เป็น snapshot ไว้ การลบสินค้าจึงไม่แตะออร์เดอร์หรือ `shop_orders.slip_path` เลย อีกทั้ง `POST /api/shop/slip` อัปโหลดสลิปก่อนสร้างออร์เดอร์ รูปที่ถูกเปลี่ยนหรือทิ้งไว้จึงกลายเป็นไฟล์กำพร้าใน `.uploads-private/slips` โดยไม่มี GC แบบที่ฟอร์มมี (`form-file-gc.ts`)
- **สคริปต์ใหม่ `scripts/purge-shop-slips.ts`:** รันด้วย `npx tsx` และเป็น dry run เป็นค่าเริ่มต้น มี `--list-products` สำหรับดูชื่อสินค้าที่ตรงเป๊ะ (รวมสินค้าที่ลบไปแล้ว), `--product "<ชื่อ>"` เลือกเฉพาะออร์เดอร์ที่ทุกบรรทัดเป็นสินค้านั้น ออร์เดอร์ที่ปนสินค้าอื่นจะถูกข้าม และ `--orphans` เลือกไฟล์สลิปที่ชื่อเป็น UUID ที่แอปสร้าง ไม่มีออร์เดอร์ไหนอ้างถึง และเก่ากว่า 24 ชั่วโมง โดย dry run จะแสดงจำนวนออร์เดอร์แยกตามสถานะ ช่วงวันที่ ขนาดไฟล์ และอีเมลผู้ซื้อให้ตรวจก่อนลบ
- **ความปลอดภัย:** `--apply` บน prod ต้องมี `CONFIRM=yes` ตาม `src/db/guard.ts` และต้องระบุ `--actor <อีเมลแอดมิน>` ที่เป็น `admin` หรือ `super_admin` การลบออร์เดอร์กับการเขียน `audit_logs` อยู่ใน transaction เดียวกัน ส่วนไฟล์จะลบหลัง commit และจะไม่ลบไฟล์ที่ยังมีออร์เดอร์อื่นอ้างถึง ถ้าลบไฟล์ไม่สำเร็จไฟล์นั้นจะกลายเป็นสลิปกำพร้าที่รอบ `--orphans` ถัดไปเก็บให้
- **Storage:** เพิ่ม `deleteSlip()` และ `listSlips()` ใน `src/lib/shop-storage.ts` ซึ่งทำงานได้ทั้ง Supabase bucket และดิสก์ local ที่ใช้บน self-hosted
- **PDPA:** สลิปมีชื่อและข้อมูลบัญชีธนาคาร การลบทุกครั้งจึงถูกบันทึกใน audit log พร้อมชื่อแอดมินที่สั่ง ไม่มีการแตะข้อมูลการแพทย์
- **เวอร์ชัน:** `package.json` ปรับเป็น 2.18.1 ให้ตรงกับ tag
- **DB/migration:** ไม่มีการแก้ schema และไม่ต้อง migrate แต่ต้อง rebuild image เพื่อให้สคริปต์อยู่ในคอนเทนเนอร์
- **ตรวจสอบแล้ว:** รันกับฐานข้อมูล local ได้ผลว่า dry run รายงานออร์เดอร์และสลิปกำพร้าถูกต้อง `--apply` ที่ไม่มี `--actor` ถูกปฏิเสธ การรันจริงลบออร์เดอร์ทดสอบ 4 รายการและไฟล์สลิป 12 ไฟล์ (1.37 MB) แล้ว dry run รอบถัดไปเหลือสลิปกำพร้า 0 ไฟล์ และ audit hash chain ยัง intact ส่วน `npm run build` ผ่าน lint ไม่มี error ใหม่ (error เดียวเป็นของเดิมใน `battle-flow.test.ts`) ยังไม่ได้รันกับ prod

# ActiveCAMT v2.18.2 🎉

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **กล้องแจกรางวัลไม่ดำหลังกด "สแกนใหม่" หรือ "คนถัดไป" แล้ว** ก่อนหน้านี้พอสแกนเจอนักศึกษาหนึ่งคนแล้วกดสแกนใหม่หรือกดคนถัดไป กล่องกล้องจะกลายเป็นสีดำทั้งกล่อง ต้องปิดหน้าต่างแล้วเปิดใหม่ถึงจะสแกนต่อได้ ตอนนี้กล้องกลับมาเองทุกครั้ง ใช้ได้ทั้งหน้าการรับรางวัลและแท็บรางวัลในหน้าเครื่องสแกน
- ถ้าเลือกนักศึกษาจากช่องค้นหาในขณะที่กล้องยังเปิดไม่เสร็จ (เช่นตอนที่เบราว์เซอร์กำลังขอสิทธิ์กล้อง) กล้องตัวนั้นจะถูกปิดให้เรียบร้อย ไม่ค้างเปิดอยู่เบื้องหลัง

## ฝั่งทีม (technical changelog)

- **Bug (กล้อง):** ตอนที่แสดงผลการสแกนหรือการ์ดบันทึกแล้ว หน้าจอสแกนจะถูก unmount ไปพร้อมกับ `#prize-qr-reader` แต่ instance ของ `html5-qrcode` จะหยุดก็ต่อเมื่อ state `scanning` เป็น false ซึ่งไม่เคยเกิดขึ้นเลย การเรียก `setScanning(true)` ตอนรีเซ็ตจึงไม่ทำให้ effect รันใหม่ ไม่มี scanner ตัวใหม่ผูกกับ div ใหม่ กล่องจึงเห็นแค่พื้นหลังสีดำของ viewfinder
- **แก้ใน `src/app/admin/prizes/PrizeAwardPanel.tsx`:** เอา state `scanning` ออก และให้กล้องทำงานเฉพาะตอนที่หน้าจอสแกนแสดงอยู่ (`!preview && !committed`) การหยุดกล้องทุกครั้งต่อกันเป็น promise chain โดยการเปิดกล้องใหม่จะรอให้ stream เดิมถูกปล่อยก่อน เพราะมือถือหลายรุ่นไม่ยอมเปิดกล้องซ้ำระหว่างที่ stream เก่ายังปิดไม่เสร็จ และถ้า `start()` เสร็จหลังจากหน้าจอเปลี่ยนไปแล้วจะสั่งหยุดซ้ำอีกรอบ
- **เวอร์ชัน:** `package.json` ปรับเป็น 2.18.2 ให้ตรงกับ tag
- **DB/migration:** ไม่มีการแก้ schema และไม่ต้อง migrate
- **ตรวจสอบแล้ว:** `npm run build` ผ่าน และ eslint ของไฟล์ที่แก้ไม่มีปัญหา (error เดียวทั้ง repo เป็นของเดิมใน `battle-flow.test.ts`) ยังไม่ได้ทดสอบกับกล้องจริงบนมือถือ

# ActiveCAMT v2.19.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **ติดตามได้ว่าของที่สั่งอยู่ตรงไหนแล้ว** ในแท็บคำสั่งซื้อของฉัน ออร์เดอร์ที่จ่ายเงินแล้วจะบอกสถานะการส่งมอบ เช่น ผู้ขายกำลังเตรียมของ พร้อมให้รับ จัดส่งแล้ว หรือได้รับสินค้าแล้ว
- **รับเอง:** พอผู้ขายกด "พร้อมให้รับ" จะมีแจ้งเตือนพร้อมบอกสถานที่และเวลารับ ตอนไปรับแค่เปิด Digital ID ให้ผู้ขายสแกน มีปุ่มลัดเปิด Digital ID ให้ในหน้าออร์เดอร์เลย
- **ส่งไปรษณีย์หรือขนส่ง:** เห็นชื่อบริษัทขนส่งและเลขพัสดุ กดคัดลอกเลขพัสดุหรือกด "ติดตามพัสดุ" เพื่อเปิดหน้าติดตามของขนส่งได้ ได้ของแล้วกด "ได้รับสินค้าแล้ว" ถ้าลืมกด ระบบจะยืนยันให้เองใน 7 วัน
- **ของมีปัญหา:** ถ้ายังไม่ได้ของ ของเสียหาย หรือได้ของผิด กด "แจ้งปัญหา" แล้วพิมพ์เล่าได้เลย ผู้ขายจะได้รับแจ้งเตือนทันที

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **สแกน Digital ID ตอนส่งมอบของ** ในแท็บคำสั่งซื้อมีปุ่มใหญ่ "สแกน Digital ID เพื่อส่งมอบสินค้า" สแกนแล้วจะเห็นออร์เดอร์ที่จ่ายเงินแล้วของคนนั้นทันที ติ๊กเลือกแล้วกดส่งมอบ ใช้ได้ทั้งตอนผู้ซื้อมารับเองและตอนเดินไปส่งในมหาวิทยาลัย
- **กันส่งผิด:** ออร์เดอร์ที่ยังไม่ได้ตรวจสลิปจะขึ้นเตือนว่าห้ามส่งมอบและกดส่งมอบไม่ได้ ส่วนออร์เดอร์ที่รับไปแล้วจะขึ้นว่ารับไปเมื่อไหร่และใครเป็นคนส่งมอบ จึงไม่มีทางให้ของซ้ำ
- **ส่งทางขนส่ง:** กด "บันทึกการจัดส่ง" เลือกบริษัทขนส่ง (ไปรษณีย์ไทย, Flash, KEX, J&T, SPX, Ninja Van, ส่งด่วนในวันอย่าง Lalamove, Grab, LINE MAN หรือพิมพ์ชื่อเอง) แล้วใส่เลขพัสดุ ระบบจะแจ้งผู้ซื้อให้เอง ถ้าพิมพ์เลขผิดกดแก้ได้
- **ตัวกรองใหม่** "รอส่งมอบ" "จัดส่งแล้ว" และ "แจ้งปัญหา" ช่วยให้เห็นทันทีว่าใครยังไม่ได้มารับของ และออร์เดอร์ไหนมีปัญหา
- ถ้ากดส่งมอบผิดคน กด "ยกเลิกการส่งมอบ" เพื่อย้อนกลับได้ ส่วนออร์เดอร์ที่ส่งมอบหรือจัดส่งไปแล้วจะปฏิเสธหรือย้อนเป็นรอตรวจสอบไม่ได้จนกว่าจะยกเลิกการส่งมอบก่อน
- ออร์เดอร์เก่าทั้งหมดจะเริ่มที่สถานะ "รอส่งมอบ" เพราะระบบไม่รู้ว่าอันไหนรับไปแล้ว ของที่แจกไปก่อนหน้านี้กด "ส่งมอบแล้ว" ย้อนหลังได้

## ฝั่งทีม (technical changelog)

### ติดตามการส่งมอบสินค้าในร้านค้า (PR #269, merge commit `9ab18ab`)

- **Data model:** เพิ่ม `shop_orders.fulfillment_status` แยกจาก `status` เดิมที่ใช้กับการตรวจสลิปอย่างเดียว ค่าคือ `awaiting`, `ready`, `shipped`, `picked_up`, `delivered`, `issue` และเพิ่มคอลัมน์ขนส่ง (`carrier`, `carrier_name`, `tracking_number`, `tracking_url`, `shipped_at`, `shipped_by`) การส่งมอบ (`fulfilled_at`, `fulfilled_by`, `fulfilled_via` ซึ่งเป็น `qr`/`manual`/`buyer`/`auto`, `fulfillment_note`) และการแจ้งปัญหา (`issue_note`, `issue_at`)
- **ตาราง transition เดียว:** `nextFulfillmentStatus()` ใน `src/lib/shop-fulfillment.ts` เป็นตัวตัดสินว่า action ไหนทำได้จากสถานะไหน ทั้งปุ่มใน UI และทุก route ใช้ตัวเดียวกัน ไฟล์นี้ไม่มี DB import จึงใช้ฝั่ง client ได้ ส่วน `src/lib/shop-fulfillment-server.ts` เก็บ patch ของแต่ละ action และตัว auto-confirm
- **Routes ใหม่:** `PATCH /api/admin/shop/orders/[id]/fulfillment` (ready, ship, handover, reset), `POST /api/admin/shop/fulfillment/scan` (preview แล้ว confirm แบบเดียวกับบูธแจกรางวัล) และ `PATCH /api/shop/orders/[id]/fulfillment` สำหรับผู้ซื้อ (confirm, report) ที่ใช้ได้กับออร์เดอร์ของตัวเองเท่านั้น
- **สิทธิ์เข้าถึง:** ใช้ scope เดียวกับการตรวจสลิป ผู้ขายหรือประธานชมรม/สาขาทำได้เฉพาะออร์เดอร์ที่ทุกรายการเป็นของตัวเอง (`classifyOrdersByScope().fullyOwned`) ตอน confirm การสแกนจะตรวจ QR ซ้ำและ lock ทุกออร์เดอร์ ต้องเป็นของผู้ซื้อที่สแกน จ่ายเงินแล้ว และยังส่งมอบได้ ส่วน route ตรวจสลิปเดิมจะปฏิเสธ reject/revert เมื่อของออกจากผู้ขายไปแล้ว
- **Auto-confirm:** self-hosted ไม่มี cron จึงรัน `autoConfirmDueShipments()` ตอนโหลดรายการออร์เดอร์ทั้งฝั่งผู้ซื้อและแอดมิน เป็น idempotent และไม่ยืนยันออร์เดอร์ที่ผู้ซื้อแจ้งปัญหาไว้
- **ลิงก์ติดตามพัสดุ:** เปิดหน้าติดตามทางการของแต่ละขนส่งและคัดลอกเลขให้ก่อน ไม่สร้าง deep link ที่ใส่เลขใน URL เพราะไม่มีขนส่งไหนประกาศรูปแบบที่แน่นอนไว้ ลิงก์ที่ผู้ขายใส่เองต้องเป็น `https://` เท่านั้น
- **Audit/PDPA:** ทุก action ของ staff รวมถึงการสแกน preview ถูกบันทึกใน `audit_logs` ส่วนการยืนยันของผู้ซื้อและ auto-confirm บันทึกไว้ในแถวออร์เดอร์ ไม่มีการแตะข้อมูลการแพทย์ และ response ฝั่งผู้ซื้อไม่ส่ง id ของ staff ออกไป

# ActiveCAMT v2.20.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **รับของทีละชิ้นได้แล้ว** ถ้าสั่งหลายอย่างในออร์เดอร์เดียว เช่น เสื้อกับฮู้ด แล้วได้เสื้อไปก่อน หน้าคำสั่งซื้อจะบอกว่าได้รับแล้วกี่รายการจากทั้งหมด มีเครื่องหมายถูกที่ของที่ได้แล้ว และบอกชัดว่ายังเหลืออะไรต้องไปรับ พร้อมปุ่มเปิด Digital ID

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **เลือกสินค้าก่อนสแกน** ปุ่มในแท็บคำสั่งซื้อเปลี่ยนเป็น "ส่งมอบสินค้า (สแกน Digital ID)" กดแล้วให้เลือกก่อนว่ากำลังแจกสินค้าอะไร (มีรูป ชื่อผู้ขาย ราคา และจำนวนคนที่รอรับ) แล้วค่อยสแกน หลังสแกนจะติ๊กได้เฉพาะสินค้าตัวนั้น ของอื่นที่คนนั้นสั่งไว้จะขึ้นเป็นสีเทาให้รู้ว่าไม่ใช่ของที่จุดนี้
- **สินค้าชื่อซ้ำกันจะมีเตือน** ถ้ามีสินค้าสองตัวชื่อเหมือนกัน (เช่น หลายชมรมขาย "เสื้อ") รายการจะขึ้นกรอบสีส้มพร้อมบอกให้ตรวจชื่อผู้ขายให้ตรง
- **แท็บ "ร้านค้า" ในหน้าเครื่องสแกน** อยู่ข้างเช็คอิน ให้คะแนน และแจกรางวัล ทีมงานที่ประจำบูธส่งมอบของได้โดยไม่ต้องออกจากหน้าสแกน
- **กล้องกว้างขึ้น** กรอบสแกนของร้านค้าใช้แบบเดียวกับหน้าแจกรางวัล กล่องใหญ่และกรอบขาวกว้าง เล็ง QR ง่ายขึ้น
- **ส่งมอบทีละรายการ** ออร์เดอร์ที่ส่งมอบไปบางส่วนจะขึ้นว่า "ส่งมอบแล้ว 1/2" บนการ์ด พร้อมบอกว่ายังเหลืออะไร และยังอยู่ในตัวกรอง "รอส่งมอบ" จนกว่าจะส่งครบ
- **กันกดพลาด:** ไซส์และจำนวนตัวใหญ่ที่สุดบนจอ ถ้าไม่มีอะไรต้องให้คนนี้จะขึ้นกล่องแดง "ไม่ต้องส่งมอบ" ไว้บนสุด ของที่รับไปแล้ว ยังไม่จ่ายเงิน หรือส่งทางไปรษณีย์จะขึ้นเตือนแยกสี ปุ่มยืนยันบอกจำนวนชิ้นที่ต้องให้ QR เดิมจะไม่ถูกสแกนซ้ำภายในไม่กี่วินาทีหลังส่งมอบ และหน้าสำเร็จมีปุ่ม "ยกเลิก (กดผิด)" ส่วนการแตะนอกหน้าต่างจะไม่ปิดผลสแกนทิ้ง
- **ส่งมอบเองแบบไม่สแกน** บนการ์ดเปลี่ยนเป็นรายการให้ติ๊กทีละชิ้น โดยไม่มีอะไรติ๊กไว้ให้ก่อน พร้อมเตือนให้ใช้การสแกนถ้าผู้ซื้ออยู่ตรงหน้า ส่วนปุ่ม "ยกเลิกการส่งมอบ" ย้ายไปอยู่บรรทัดแยกให้ห่างจากปุ่มหลัก
- แก้ไขรายการในออร์เดอร์ที่ส่งมอบไปแล้วไม่ได้ ต้องยกเลิกการส่งมอบก่อน เพื่อให้ข้อมูลตรงกับของที่ผู้ซื้อได้รับจริง

## ฝั่งทีม (technical changelog)

### ส่งมอบรายชิ้นและเลือกสินค้าก่อนสแกน (PR #270, merge commit `a9c9d07`)

- **Data model:** เพิ่ม `shop_order_items.handed_over_at` และ `handed_over_by` เพื่อบันทึกการส่งมอบรายบรรทัด และเพิ่มสถานะ `partial` ใน `shop_orders.fulfillment_status` สำหรับออร์เดอร์ที่ส่งมอบไปบางส่วน `isItemHandedOver()` นับทุกบรรทัดของออร์เดอร์ที่จบแล้วว่าส่งมอบแล้ว จึงไม่ต้อง backfill
- **กฎใหม่ใน `src/lib/shop-fulfillment.ts`:** `statusAfterItemHandover()` และ `statusAfterItemUndo()` ออร์เดอร์ที่ส่งทางไปรษณีย์ (`shipped`/`issue`) ต้องปิดทั้งพัสดุพร้อมกัน ส่วน `partial` ทำให้ reject/revert ถูกปฏิเสธเหมือนสถานะอื่นที่ของออกไปแล้ว
- **Server:** `handOverItems()` และ `undoItemHandover()` ใน `src/lib/shop-fulfillment-server.ts` lock ออร์เดอร์แล้วอ่านบรรทัดใหม่ภายใต้ lock ตรวจว่าเป็นของผู้ซื้อที่สแกน เป็นสินค้าที่เลือก จ่ายเงินแล้ว และยังไม่ถูกส่งมอบ ใช้ร่วมกันทั้งปุ่มบนการ์ดและเครื่องสแกน
- **Routes:** เพิ่ม `GET /api/admin/shop/fulfillment/products` สำหรับตัวเลือกสินค้าพร้อมจำนวนที่รอ `POST /api/admin/shop/fulfillment/scan` รับ `productId` และมี action `undo` เพิ่ม ส่วน handover ใน `PATCH .../fulfillment` ต้องส่ง `itemIds` และ reset จะล้างการส่งมอบรายบรรทัดด้วย route แก้ไขออร์เดอร์ปฏิเสธการแก้บรรทัดที่ส่งมอบแล้ว
- **สิทธิ์เข้าถึง:** แท็บร้านค้าในหน้าเครื่องสแกนเปิดตาม `isShopManager` ส่วนบัญชีที่เป็นผู้ขายอย่างเดียวยังเข้าหน้าเครื่องสแกนไม่ได้ตามเดิมจึงใช้ปุ่มในหน้าร้านค้าแทน ทุก route ใช้ `resolveShopAccess` ผู้ใช้แบบมี scope เห็นเฉพาะสินค้าของตัวเอง (`filterProductsByScope`) และทำได้เฉพาะออร์เดอร์ที่เป็นของตัวเองทั้งหมด
- **Mobile/UI:** ย้ายสไตล์ viewfinder ของหน้าแจกรางวัลไปเป็น `src/components/admin/QrViewfinder.module.css` ใช้ร่วมกันทั้งสองเครื่องสแกน คอมโพเนนต์ใหม่คือ `ShopHandoverProducts.tsx` และ `ScannerShopTab.tsx` ส่วน `ShopHandoverScanner.tsx` เขียนใหม่ทั้งหมด
- **Audit/PDPA:** ทุกการส่งมอบและยกเลิกถูกบันทึกใน `audit_logs` ทีละออร์เดอร์พร้อมรายการที่เกี่ยวข้อง ไม่มีการแตะข้อมูลการแพทย์
- **DB/migration:** `src/db/migrate.ts` step 98 (ตรงกับ `drizzle/0046_safe_captain_midlands.sql`) เป็น `ADD COLUMN IF NOT EXISTS` สองคอลัมน์ ไม่มี DELETE หรือ DROP รันบน prod แล้วก่อน merge
- **Deploy:** พบว่าการ merge เข้า `main` จะ redeploy prod อัตโนมัติผ่าน Portainer webhook ใน `docker-publish.yml` จึงต้องรัน migration บน prod ก่อน merge ทุกครั้ง
- **เวอร์ชัน:** `package.json` ปรับเป็น 2.20.0 ให้ตรงกับ tag
- **ตรวจสอบแล้ว:** unit test 352 ตัวผ่าน (ใหม่ 7 ตัว) `npm run build` ผ่าน lint ไม่มี error ใหม่ (error เดียวเป็นของเดิมใน `battle-flow.test.ts`) รัน migration บน local สองรอบ รันทดสอบ API แบบ end-to-end 44 ขั้นบน local ผ่านทั้งหมด และทดสอบในเบราว์เซอร์ด้วยกล้องจำลองที่แสดง QR ของผู้ซื้อจริง ตั้งแต่เลือกสินค้า สแกน ส่งมอบ จนถึงสแกนซ้ำแล้วขึ้นว่ารับไปแล้ว ยังไม่ได้ทดสอบด้วยกล้องมือถือจริงบน prod
