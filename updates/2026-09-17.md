## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **แก้ checkbox "Require check-out" ในหน้าแก้ไขกิจกรรม (`/admin/events`) ให้กดติดง่ายขึ้น** เดิมต้องกดตรงกล่องเล็ก ๆ เป๊ะ ๆ เท่านั้นถึงจะติ๊กได้ ตอนนี้กดตรงไหนของแถวก็ได้ (ไอคอน ข้อความ หรือกล่อง) แล้วติ๊กถูกครั้งเดียวแน่นอน พร้อมเปลี่ยนหน้าตากล่องติ๊กให้เป็นสไตล์ของแอปเอง แทนกล่องติ๊กมาตรฐานของเบราว์เซอร์
- **แก้ไขรายละเอียดคำสั่งซื้อในร้านค้าได้แล้วหลังลูกค้าสั่งซื้อไปแล้ว** ถ้าลูกค้าลืมเลือกไซส์/ตัวเลือก กรอกชื่อ-เบอร์บนเสื้อผิด หรือที่อยู่จัดส่งพิมพ์ผิด แอดมินหรือเจ้าของร้าน (ประธานชมรม/สาขา/ผู้ขาย) กดปุ่ม "แก้ไขรายละเอียด" ในหน้ารายการคำสั่งซื้อ (`/admin/shop`) เพื่อแก้ให้ถูกต้องได้เลย โดยไม่ต้องให้ลูกค้าสั่งใหม่ ใช้ได้กับคำสั่งซื้อทุกสถานะ ทั้งที่รออนุมัติ อนุมัติแล้ว หรือถูกปฏิเสธไปแล้ว
- **เปลี่ยนชื่อสินค้าหรือชื่อตัวเลือกในร้านค้าแล้ว ออร์เดอร์เก่าจะอัปเดตตามให้อัตโนมัติ** ไม่ต้องกังวลว่ารายการคำสั่งซื้อในหน้าแอดมินจะแยกเป็นชื่อเก่า/ชื่อใหม่คนละกลุ่มอีกต่อไปหลังเปลี่ยนชื่อสินค้า

## ฝั่งทีม (technical changelog)

### แก้ปุ่มติ๊ก require-checkout กดพลาดง่าย (PR #230, merge commit `395a853`)

- **Bug:** `<label>` ของ checkbox มีทั้ง `onClick` ที่สั่ง toggle state เอง และการส่งต่อคลิกแบบ native ของ `<label>` ที่ครอบ `<input type="checkbox">` อยู่แล้ว ทำให้สองกลไกนี้ชนกันเองจนกดที่ข้อความ/ไอคอนไม่ค่อยติด ต้องกดตรงกล่องเล็ก ๆ เป๊ะ ๆ เท่านั้น
- **แก้ไข:** เอา `onClick` ที่ซ้ำซ้อนออก ให้เหลือแค่ `onChange` บน input เหมือน pattern ที่ใช้อยู่แล้วในไฟล์เดียวกัน (เช่น checkbox กรองนักศึกษาไทย/นานาชาติ) พร้อมเปลี่ยนกล่องติ๊กเป็นสไตล์ custom (กรอบ/พื้นสีธีม + ไอคอนถูกจาก Lucide) โดย input จริงยังอยู่ครอบเต็มกล่องแบบไม่แสดงผล เพื่อคง accessibility/form semantics เดิม
- ไม่มีการเปลี่ยน schema/DB เป็น UI fix ล้วน ตรวจสอบแล้วด้วย `npm run build` และ `npx tsc --noEmit` ผ่านครบ ไม่มี error ใหม่

### ให้แอดมิน/เจ้าของร้านแก้ไขคำสั่งซื้อได้ พร้อม sync ชื่อสินค้า/ตัวเลือกที่เปลี่ยนไปยังออร์เดอร์เก่า (PR #231, merge commit `f1a2314`)

- **Feature:** เพิ่ม `PUT /api/admin/shop/orders/[id]` ให้แอดมินร้าน (หรือประธานชมรม/สาขา/ผู้ขายที่ scoped) แก้ไขตัวเลือก (variant), ข้อความ "ระบุเอง" (Other specify), คำตอบช่องกรอกเอง (custom fields), หมายเหตุ, และข้อมูลผู้รับ/ที่อยู่จัดส่ง (เฉพาะออร์เดอร์แบบจัดส่ง) ของคำสั่งซื้อที่มีอยู่แล้วได้ทุกสถานะ ทั้ง pending/approved/rejected แก้ปัญหาที่ผู้ซื้อลืมเลือกตัวเลือกหรือกรอกไม่ครบตอนสั่งซื้อ
- **สิทธิ์เข้าถึง:** ใช้ gate เดียวกับปุ่มอนุมัติ/ปฏิเสธเดิมทุกประการ คือ `resolveShopAccess` ร่วมกับ `classifyOrdersByScope` แบบ fullyOwned ประธานที่ scoped แก้ไขได้เฉพาะออร์เดอร์ที่ทุกรายการเป็นของชมรม/สาขาตัวเองเท่านั้น และทุกการแก้ไขถูกบันทึกลง audit log แบบ append-only เหมือน action อื่นในหน้านี้ ตรวจสอบเพิ่มเติมด้วย pdpa-access-guard subagent แล้วไม่พบช่องโหว่เรื่องสิทธิ์เข้าถึงหรือ PII
- **แก้บั๊ก re-price ที่พบระหว่างพัฒนา:** ถ้าไม่ระวัง การแก้ไขจะคำนวณราคาของทุกรายการใหม่ตามราคาสินค้าปัจจุบันเสมอ แม้รายการนั้นไม่ได้ถูกแตะเลย ตอนนี้จะคำนวณราคาใหม่เฉพาะรายการที่ตัวเลือก/คำตอบเปลี่ยนจริงเท่านั้น ราคาของรายการที่ไม่ได้แก้ไขจะคงเดิมตามตอนซื้อ พร้อม re-validate stock ภายใต้ row lock เดียวกับ flow revert เดิม เพื่อกันการ race กับการแก้ไข/สั่งซื้อพร้อมกัน
- **แก้ sync ชื่อสินค้า/ตัวเลือก:** เดิมเปลี่ยนชื่อสินค้าหรือชื่อตัวเลือก (variant label) แล้วออร์เดอร์เก่าที่สั่งไปแล้วจะยังโชว์ชื่อเดิมตลอดไป ทำให้ filter/รายงานแยกเป็นสองชื่อ ตอนนี้เปลี่ยนชื่อสินค้า/ตัวเลือกจะ sync ไปยังทุกออร์เดอร์เก่าที่ใช้ชื่อนั้น รวมออร์เดอร์ที่ approved/rejected ไปแล้วด้วย โดยจับคู่ prefix แบบ exact string (ไม่ใช้ SQL `LIKE` wildcard) เพื่อกันเคสชื่อที่มีอักขระ `%`/`_` หลุดไปแมตช์ผิดแถว
- ไม่มีการเปลี่ยน schema/DB ตรวจสอบแล้วด้วย `npm run lint`, `npx tsc --noEmit`, `npm run build`, และ `npm test` (216 tests) ผ่านครบ ไม่มี error ใหม่
