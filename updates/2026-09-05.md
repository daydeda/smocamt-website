## ฝั่งทีม (technical changelog)

### แก้บั๊กเซสชันไม่หมดอายุเมื่อผู้ใช้ถูกลบ และล้างข้อความ @cmu.ac.th ที่ค้างอยู่ (PR #225)

- **สิทธิ์เข้าถึง/ความปลอดภัย:** `jwt` callback ใน `src/auth.ts` จะคืนค่า `null` (ซึ่งทำให้เซสชันเป็นโมฆะทันที) ทุกครั้งที่ผู้ใช้ในฐานข้อมูลที่ผูกกับ token นั้นไม่มีอยู่แล้ว ครอบคลุมทั้งตอนล็อกอินใหม่ ตอน trigger "update" และตอน refresh เป็นระยะ ก่อนหน้านี้ถ้าแอดมินลบบัญชีใครไป เซสชันเดิมของคนนั้นยังใช้งานต่อได้เงียบ ๆ จนกว่าคุกกี้จะหมดอายุเอง (นานสุด 7 วัน) ตอนนี้แก้แล้วว่าถ้า token ไม่มี user id ก็จะถือเป็นโมฆะเช่นกัน
- **แก้ข้อความล้าสมัย:** ลบคอมเมนต์และข้อความ i18n (EN/TH/MM/CN) ที่อ้างว่ามีการบังคับโดเมน @cmu.ac.th ทั้งใน `src/auth.ts`, `src/lib/i18n.ts` และ README เพราะฟีเจอร์นี้ยังไม่ live จริง (ตาม `CLAUDE.md`) ข้อความตอนนี้ตรงกับพฤติกรรมจริงแล้ว
- **แพ็กเกจ:** อัปเดต `next`, `next-auth`, `@auth/drizzle-adapter`, `nodemailer` (major bump 7 → 8), `sharp`, `eslint-config-next` เป็นเวอร์ชันล่าสุดที่ใช้งานร่วมกันได้
- **เทสต์:** เพิ่ม `src/auth.test.ts` คลุมทั้งสองพฤติกรรมใหม่ (mock DB/adapter ทั้งหมด ไม่แตะฐานข้อมูลจริง)
- ตรวจสอบแล้วด้วย `npm test` (177 ผ่านทั้งหมด), `npm run lint`, และ `npm run build` ไม่พบ error ใหม่จากไฟล์ที่แก้ในรอบนี้ แนะนำให้ทดสอบส่งอีเมลแจ้งเตือน feedback อีกครั้งเพราะ `nodemailer` เป็น major bump และให้รัน `/verify` เพื่อยืนยันว่าลบผู้ใช้แล้วเซสชันจริงหลุดออกจากระบบ
