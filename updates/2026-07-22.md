- **เช็คอินผ่านแอป Songsue ก็จะนับเข้าร่วมกิจกรรมใน ActiveCAMT ให้อัตโนมัติด้วย** — กิจกรรมที่เชื่อมกับ Songsue ถ้านักศึกษาเช็คอินผ่านเครื่องสแกนฝั่ง Songsue (เช่นงานที่จัดร่วมกัน) ระบบ ActiveCAMT จะบันทึกว่าเข้าร่วมให้อัตโนมัติ ไม่ต้องมาเช็คอินซ้ำสองรอบสองแอป

## ฝั่งทีม (technical changelog)

### ฟีเจอร์ใหม่: Bidirectional Songsue sync + auth cookie namespacing fix (PR #199)

- **`src/app/api/integrations/songsue/checkin/route.ts`** (ใหม่) — inbound endpoint รับการเช็คอินจากฝั่ง Songsue เอง (เดิมมีแค่ทิศทาง ActiveCAMT → Songsue) ยืนยันตัวตนด้วย bearer secret เดียวกัน (`ACTIVECAMT_SYNC_SECRET`, constant-time compare ใน `src/lib/integration-auth.ts`), rate-limit 300 req/min ต่อ IP, validate ด้วย Zod — upsert นักศึกษาด้วย email แล้ว mark attended บน session ปัจจุบันของกิจกรรมนั้น (`src/modules/integrations/songsue-sync.service.ts`) 404 ถ้ากิจกรรมไม่ได้เชื่อม Songsue, 409 ถ้ากิจกรรมยังไม่มี session
- กิจกรรมที่เชื่อมกับ Songsue ตอนนี้ sync `walkInsEnabled`/`quota`/`quotaWalkIn` ไปด้วย เพื่อให้การเช็คอิน walk-in ผ่านเครื่องสแกนฝั่ง Songsue ทำงานตรงกับการตั้งค่าจริงของกิจกรรม (เดิมฝั่ง Songsue จะ default เป็นปิด walk-in/ไม่จำกัดโควตาเสมอ)
- **PDPA — payload การ sync ลงทะเบียน/เช็คอิน (ทั้ง 2 ทิศทาง) ตอนนี้ส่งข้อมูลสุขภาพและผู้ติดต่อฉุกเฉินไปด้วย** ไม่ใช่แค่ identity field เหมือนเดิม — เป็นการตัดสินใจเชิงผลิตภัณฑ์ที่ตกลงร่วมกับฝั่ง Songsue (ฝั่ง Songsue เขียนข้อมูลนี้เฉพาะตอนสร้างบัญชีใหม่ หรือเติมเฉพาะช่องที่ยังว่างของบัญชีเดิม ไม่ทับข้อมูลที่กรอกไว้แล้ว) — PDPA consent ของ ActiveCAMT เองไม่ถูกนับเป็น consent ของฝั่ง Songsue โดยอัตโนมัติ
- **แก้จุดสิทธิ์เข้าถึง (พบระหว่าง `/recheck` ก่อน merge):** ปุ่ม manual resync ของสตาฟ (จาก PR #197) ตอนนี้ backfill ข้อมูลผู้เข้าร่วมทุกคนของกิจกรรมไปยัง Songsue ด้วย ไม่ใช่แค่ตัวกิจกรรม — เดิม role ที่เรียกได้คือ `registration`/`organizer` เหมือนปุ่มอื่น ๆ ในกลุ่มนี้ แต่เพราะตอนนี้ปุ่มนี้ส่งข้อมูลสุขภาพ/ผู้ติดต่อฉุกเฉินแบบละเอียดของผู้เข้าร่วมทุกคนออกไปนอกระบบ (ซึ่งปกติ `registration`/`organizer` เห็นแค่ "มี/ไม่มี" ไม่เห็นรายละเอียด ตามนโยบายเดิม) จึงจำกัดสิทธิ์ปุ่มนี้ให้เหลือแค่ `super_admin`/`admin` และปรับ audit log ให้ระบุชัดว่ามีการส่งข้อมูลอ่อนไหวไปด้วยกี่คน
- **`src/auth.ts`:** ตั้งชื่อ cookie ของ Auth.js ใหม่ทั้งหมด (`activecamt.*`) เพราะ cookie ของ Auth.js ผูกกับ hostname+path เท่านั้น ไม่แยกตาม port — ตอน dev ในเครื่อง ActiveCAMT (localhost:3001) กับ Songsue (localhost:3000) จะเผลอใช้ cookie ตัวเดียวกันทับกัน ทำให้ signOut ของแอปหนึ่งไปตัด session ของอีกแอปโดยไม่ตั้งใจ — แก้เฉพาะชื่อ cookie เท่านั้น ค่า `httpOnly`/`secure`/`sameSite` ยังเป็นค่า default เดิมของ Auth.js
