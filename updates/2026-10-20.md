# อัปเดต ActiveCAMT ประจำวันที่ 20 ต.ค. 69

สรุปสำหรับวันที่ 20 ต.ค. 69 เอาไว้ลง Discord และให้ทีมที่เกี่ยวข้องอ่านกัน

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **ระบบให้ตรวจสอบข้อมูลส่วนตัวทุก 3 เดือน** เมื่อเข้าหน้าแรกหรือหน้าโปรไฟล์ จะมีป๊อปอัปถามว่า "ข้อมูลของคุณยังเป็นปัจจุบันอยู่ไหม" เพื่อให้ข้อมูลส่วนตัว ข้อมูลสุขภาพ และผู้ติดต่อฉุกเฉินถูกต้องอยู่เสมอ ทีมงานจะได้ติดต่อคนที่ถูกต้องได้เมื่อเกิดเหตุ
- **มีสองปุ่มให้เลือก** ปุ่ม "อัปเดตข้อมูลของฉัน" พาไปหน้าโปรไฟล์เพื่อแก้ไขได้ทันที และเมื่อกดบันทึกก็ถือว่าตรวจสอบแล้ว ส่วนปุ่ม "ไม่มีการเปลี่ยนแปลง ใช้ข้อมูลเดิม" จะเก็บข้อมูลเดิมไว้และป๊อปอัปจะไม่ขึ้นอีกจนกว่าจะครบ 3 เดือน
- ทุกคนที่มีโปรไฟล์ครบแล้วจะเห็นป๊อปอัปนี้หนึ่งครั้งหลังอัปเดตรอบนี้ เพราะยังไม่เคยตรวจสอบมาก่อน ส่วนคนที่ยังกรอกข้อมูลไม่ครบจะไปหน้ากรอกข้อมูลเหมือนเดิม
- มีข้อความภาษาอังกฤษ ไทย พม่า และจีน

## ฝั่งทีม (technical changelog)

### ป๊อปอัปตรวจสอบโปรไฟล์ทุก 3 เดือน (v2.23.0, commit `7abfea0`)

- **DB/migration:** เพิ่มคอลัมน์ `users.profile_reviewed_at` (timestamp, nullable) ใน migration `0047` เป็นการเพิ่มคอลัมน์อย่างเดียว ไม่มีการลบหรือแปลงข้อมูล ต้องรัน `npm run db:migrate:container` บน prod ก่อน merge ซึ่งยืนยันแล้วว่ารันแล้ว ค่า null หมายถึงยังไม่เคยตรวจสอบ จึงถึงกำหนดทันที
- **ทำไมไม่ใช้ `updatedAt`:** คอลัมน์นั้นถูกอัปเดตจากฟีเจอร์อื่นด้วย จะทำให้นาฬิกา 3 เดือนรีเซ็ตเงียบ ๆ จึงแยกคอลัมน์ใหม่
- **กฎเดียวใช้ร่วมกัน:** `src/lib/profile-review.ts` มี `isProfileReviewDue` และ `shouldShowProfileReview` (โปรไฟล์ต้องครบก่อนจึงจะถูกถาม) พร้อมเทสต์ใหม่ 3 ตัวในหน้าโปรไฟล์และหน้า dashboard
- **API:** `POST /api/profile/review` ตั้ง `profileReviewedAt` เท่านั้น ไม่แตะฟิลด์โปรไฟล์ และต้องเป็นโปรไฟล์ที่ครบแล้ว `PATCH /api/profile` และ onboarding (`POST`) ตั้งค่านี้ด้วย
- **PDPA:** ปุ่มเก็บข้อมูลเดิมเขียน audit log ใน transaction เดียวกัน ("Self: confirmed profile info unchanged") ไม่มีการอ่านข้อมูลสุขภาพเพิ่ม และ audit log เดิมของการแก้ไขข้อมูลสุขภาพยังทำงานตามเดิม
- **สิทธิ์เข้าถึง:** ไม่แก้ `src/proxy.ts` โปรไฟล์ที่ยังไม่ครบยังถูกส่งไป `/onboarding` เหมือนเดิม
- **UI:** เพิ่ม `ProfileReviewModal` และ `ProfileReviewGate` (dashboard ดึงโปรไฟล์ครั้งเดียวตอนเปิด) ปุ่มอัปเดตจาก dashboard ไปที่ `/dashboard/profile?review=update` เพื่อไม่ให้ป๊อปอัปซ้ำ ข้อความใหม่ 5 คีย์ใน `i18n.ts` (EN/TH/MM/CN)
- **Dev tooling:** เพิ่ม `npm run db:seed:test-student` สร้างนักศึกษาทดสอบ (ข้อมูลสมมติ, review date เป็น null) รันซ้ำแล้วรีเซ็ตแถวเดิม และปฏิเสธทุกฐานข้อมูลที่ไม่ใช่ localhost โดยไม่มีทางข้าม ต่างจาก `guard.ts` ที่ข้ามด้วย `CONFIRM=yes` ได้
- **Dev Bypass Login:** เปิดฟอร์มกลับมา (เดิมถูกปิดด้วย `false &&` ใน commit `9960aff`) ยังใช้ได้เฉพาะ `NODE_ENV=development` กับ `ENABLE_DEV_LOGIN=true` และปฏิเสธฐานข้อมูลระยะไกล เพื่อไม่ให้ dropdown ของ role เขียนทับอีเมลที่พิมพ์เอง จึงเปลี่ยนอีเมลเมื่อยังเป็นค่าสำเร็จรูปเท่านั้น ควรแจ้งคนที่ปิดฟอร์มไว้
- **เทสต์:** เพิ่มคอลัมน์ใหม่ใน DDL ของตาราง `users` ที่เขียนมือใน `battle-flow.test.ts` และ `stats-helper.test.ts` ไม่งั้นเทสต์ games ล้ม
- **ตรวจสอบแล้ว:** `npm run build` ผ่าน, `npm test` 368 ตัวผ่าน, `tsc` ผ่าน และ `npm run lint` ไม่มี error ใหม่ (มี error เดิมหนึ่งจุดใน `battle-flow.test.ts`) ทดสอบทั้งสองปุ่มบน Chrome กับ Postgres ชั่วคราวในเครื่อง แต่ยังไม่ได้ทดสอบบน prod และข้อความภาษาพม่ากับจีนยังไม่มีเจ้าของภาษาตรวจ
