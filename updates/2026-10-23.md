# ActiveCAMT v2.29.0 🎉

# อัปเดต ActiveCAMT ประจำวันที่ 23 ต.ค. 69

สรุปสำหรับวันที่ 23 ต.ค. 69 เอาไว้ลง Discord และให้ทีมที่เกี่ยวข้องอ่านกัน

---

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **หน้ากิจกรรมแบบสาธารณะ:** ลิงก์กิจกรรมที่แชร์ไปใน LINE หรือ Discord จะแสดงโปสเตอร์ วันเวลา สถานที่ และที่นั่งที่จองแล้ว โดยไม่ต้องเข้าสู่ระบบก่อน
- **ผู้เยี่ยมชมที่ยังไม่ได้เข้าสู่ระบบ** ดูอันดับบ้าน ปฏิทินกิจกรรม และร้านค้าได้ ส่วนการลงทะเบียน การสั่งซื้อ และอันดับรายบุคคลยังต้องเข้าสู่ระบบก่อน
- **ปฏิทิน:** ผู้ที่ยังไม่ได้เข้าสู่ระบบสามารถติดตามปฏิทินกิจกรรมผ่าน Google Calendar หรือ Apple Calendar ได้ด้วยลิงก์สาธารณะ
- **หน้าแรก:** ผู้เข้าชมใหม่เห็นกิจกรรมที่กำลังจะมาถึง อันดับบ้าน และประกาศล่าสุดก่อนเข้าสู่ระบบ

---

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- ไม่มีการเปลี่ยนแปลงหน้าจัดการสำหรับทีมงานในรอบนี้

---

## ฝั่งทีม (technical changelog)

- **Public routes:** เพิ่ม `/e/<id>` (ผ่าน `EventsService.getPublicEvent`, ใช้ `isEligibleForGuest` และคืน 404 สำหรับกิจกรรมที่ไม่เปิดให้ผู้เยี่ยมชม) และหน้าแรก `/` สำหรับผู้ที่ยังไม่เข้าสู่ระบบ เปิด `/dashboard/houses`, `/dashboard/calendar` และ `/dashboard/shop` ให้ผู้เยี่ยมชมผ่าน `src/proxy.ts`
- **PDPA:** `/api/shop` คืนข้อมูลแบบ browse-only ให้ผู้ที่ยังไม่เข้าสู่ระบบ ไม่มีข้อมูลการชำระเงิน การจัดส่ง/รับของ หรือราคาสวัสดิการ ชื่อผู้ขายคืนเฉพาะชื่อที่แสดง อันดับรายบุคคลและฟีดกิจกรรมของบ้านยังต้องเข้าสู่ระบบ (401) เหมือนเดิม
- **ปฏิทิน:** เพิ่ม `/api/calendar/public` (.ics ไม่มี token, cache 5 นาที) และย้ายการแมปรายการปฏิทินไปไว้ `src/lib/calendar/ical.ts` (`toCalItems`) ให้ feed ส่วนตัวกับ feed สาธารณะใช้ร่วมกัน ลิงก์ของกิจกรรมใน feed ชี้ไป `/e/<id>` แล้ว
- **Access:** การเข้าถึงของผู้เยี่ยมชมทั้งหมดผ่าน `isEligibleForGuest` และใช้ข้อมูลเฉพาะที่ไม่ระบุตัวนักศึกษา
- **ไม่มีการเปลี่ยน DB schema หรือ migration** (ไม่ต้องรัน `db:migrate:container` ก่อน deploy)
- **ตรวจสอบแล้ว:** `npm run build`, `tsc`, `npm run lint` (ไม่มี error ใหม่) และ `vitest` 430 tests ผ่าน

# ActiveCAMT v2.29.3 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **การแจ้งเตือนบน iPhone (PWA):** แอปจะลงทะเบียนการแจ้งเตือนของเครื่องใหม่ให้อัตโนมัติทุกครั้งที่เปิดแอป ทำให้การแจ้งเตือนที่เคยหายไปกลับมาได้เองโดยไม่ต้องเปิดปิดใหม่ในหน้าโปรไฟล์ ถ้ายังไม่กลับมา ให้ปิดแล้วเปิดการแจ้งเตือนในหน้าโปรไฟล์หนึ่งครั้ง

## ฝั่งทีม (technical changelog)

- **Push:** `PWARegister` เรียก `resyncPushSubscription` เมื่อเปิดแอปและเมื่อกลับมาที่หน้าจอ (ไม่เกินทุก 30 นาที) เพื่อส่ง subscription เดิมของเครื่องให้เซิร์ฟเวอร์ใหม่ เพราะ iOS ไม่ยิง `pushsubscriptionchange` จึงไม่มีอะไรซ่อมแถวที่ถูกลบไปแล้ว ฟังก์ชันนี้ไม่สร้าง subscription ใหม่ จึงไม่ลงทะเบียนซ้ำให้คนที่ปิดการแจ้งเตือนไว้หรือคนที่ใช้เครื่องร่วมกัน
- **Push:** `shouldPruneAfterFailure` ลบ subscription ที่ส่งไม่สำเร็จแบบชั่วคราวเฉพาะเมื่อพลาดติดกัน 5 ครั้งและไม่เคยส่งสำเร็จเลยใน 14 วัน ส่วน 404/410 ยังลบทันที เดิมพลาด 5 ครั้งก็ลบทันทีซึ่งทำให้ช่วงที่ระบบขัดข้องปิดการแจ้งเตือนของเครื่องไปถาวร
- **ไม่มีการเปลี่ยน DB schema หรือ migration**
- **ตรวจสอบแล้ว:** `npm run build`, `tsc`, `npm run lint` (ไม่มี error ใหม่) และ `vitest` 438 tests ผ่าน; ยังไม่ได้ทดสอบบน iPhone จริง

# ActiveCAMT v2.30.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **คิวรอ (Waitlist):** ถ้ากิจกรรมเต็ม ปุ่มจะเปลี่ยนเป็น "เข้าคิวรอ" กดแล้วจะได้ลำดับคิว เมื่อมีคนยกเลิก ระบบจะลงทะเบียนให้คนแรกในคิวอัตโนมัติและส่งการแจ้งเตือน กดปุ่มคิวอีกครั้งเพื่อออกจากคิวได้ทุกเมื่อ
- **กลับมาหน้าเดิมหลังเข้าสู่ระบบ:** ถ้ากดเข้าสู่ระบบจากหน้ากิจกรรม ร้านค้า หรือหน้าบ้าน ระบบจะพากลับมาหน้าเดิมหลังล็อกอิน ไม่ต้องหาใหม่
- **เพิ่มลงปฏิทิน:** หน้ากิจกรรมสาธารณะมีปุ่มเพิ่มลง Google Calendar และ Outlook

---

## ฝั่งทีม (technical changelog)

- **DB/migration:** ตารางใหม่ `event_waitlist` (`drizzle/0051_previous_major_mapleleaf.sql`, `migrate.ts` step 103) แยกจาก `attendance` จึงไม่กระทบจำนวนที่นั่ง scanner หรือการ export ต้องรัน `db:migrate:container` บน prod ก่อน deploy ซึ่งรันแล้ว
- **Registration:** POST ของ `/api/events/[id]/register` ใส่นักศึกษาเข้าคิวเมื่อโควต้าเต็ม (202) ส่วน DELETE ออกจากคิวหรือยกเลิกแล้วเรียก `promoteFromWaitlist` ภายใต้ row lock เดียวกับการลงทะเบียน โดยเคารพโควต้ารวมและโควต้าไทย/นานาชาติ ข้ามคนที่ถูกบล็อกเพราะ no-show และ sync ไป Songsue เหมือนการลงทะเบียนปกติ
- **สิทธิ์เข้าถึง:** proxy บังคับให้ผู้ใช้ที่ยังกรอกโปรไฟล์ไม่เสร็จไปหน้า onboarding เมื่อเข้า `/dashboard/houses`, `/dashboard/calendar` และ `/dashboard/shop` ด้วย ปิดช่องโหว่ที่เกิดใน v2.29.0
- **Auth:** `/login?callbackUrl=` รับเฉพาะ path ภายในเว็บเดียวกัน (`src/lib/util/safe-callback-url.ts`) เพื่อกัน open redirect
- **ตรวจสอบแล้ว:** `npm run build`, `tsc`, `npm run lint` (ไม่มี error ใหม่) และ `vitest` 438 tests ผ่าน; ยังไม่ได้ทดสอบ query ของ waitlist กับฐานข้อมูลจริง

# ActiveCAMT v2.31.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **แจ้งเตือนก่อนแบบฟอร์มปิด:** ถ้ามีแบบทดสอบ แบบประเมินทัศนคติ หรือแบบประเมินความคิดเห็นที่ยังไม่ได้ทำ ระบบจะส่ง push เตือนก่อนปิด 24 ชั่วโมง และอีกครั้งเมื่อเหลือ 1 ชั่วโมง ผู้ที่ส่งแบบฟอร์มไปแล้วจะไม่ได้รับการแจ้งเตือน
- **กิจกรรมใหม่ให้ลงทะเบียน:** เมื่อทีมงานเปิดกิจกรรมใหม่ นักศึกษาที่เข้าร่วมได้จะได้รับ push แจ้งว่าลงทะเบียนได้แล้ว

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **หน้าโปรไฟล์:** ปุ่มทดสอบการแจ้งเตือนมีตัวอย่างใหม่สามแบบ ได้แก่ แบบฟอร์มใกล้ปิด 24 ชั่วโมง แบบฟอร์มใกล้ปิด 1 ชั่วโมง และกิจกรรมใหม่ ระบบจะส่งให้อุปกรณ์ของผู้ทดสอบเท่านั้น

## ฝั่งทีม (technical changelog)

- **Push:** เพิ่ม `ReminderService.runFormReminders` และ `GET /api/cron/reminders` (ตรวจ `CRON_SECRET` แบบ fail-closed) โดย scheduler เรียกทุก 5 นาที ผู้รับใช้กฎเดียวกับแบนเนอร์แบบฟอร์มที่ยังไม่ได้ทำ
- **Push กิจกรรมใหม่:** `getNewEventAudienceUserIds` ใช้ `isEligibleFor` โดยไม่ข้าม admin bypass และส่งหลัง response ผ่าน `after()` ไม่ส่งให้กิจกรรม walk-in-only หรือกิจกรรมที่เริ่มแล้ว
- **DB/migration:** migration step 104 และ `drizzle/0052_first_havok.sql` สร้างตาราง `form_reminders` (form_id, stage) พร้อม unique index เพื่อกันการส่งซ้ำ เพิ่มแบบ idempotent และไม่ทำลายข้อมูล รันบน prod แล้วก่อนปล่อยโค้ด
- **Scheduler:** `scripts/cron-runner.mjs` เพิ่ม job `/api/cron/reminders` ทุก 5 นาที
- **การเข้าถึง/PDPA:** ไม่มีการอ่านข้อมูลทางการแพทย์ใหม่ และไม่มีการเปลี่ยนสิทธิ์การเข้าถึง

อัปเดตรอบนี้รวม commit `31018dc` (feat(push): form-closing reminders and new-event pushes) และ release v2.31.0
