## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **QR ประจำตัว ใช้สแกนข้ามระบบได้แล้ว** — นักศึกษาที่มีทั้งบัญชี ActiveCAMT และ Songsue ตอนนี้เอา QR จากแอปไหนก็ได้ไปให้เครื่องสแกนของอีกแอปอ่านได้เลย ไม่ต้องสลับไปเปิด QR ของแอปนั้น ๆ โดยเฉพาะ ถ้าเป็นคนที่ยังไม่เคยมีบัญชี ActiveCAMT มาก่อน ระบบจะสร้างบัญชีให้อัตโนมัติจากข้อมูลฝั่ง Songsue ตอนสแกนครั้งแรก
- **แก้บัคเล็ก:** แจ้งเตือนเช็คอินที่ต้องนับถอยหลังไปหน้า Songsue (เวลาจำกัด) จะไม่ถูกแจ้งเตือนอื่นที่ค้างคิวอยู่ก่อนบังหน้าอีกต่อไป — เดิมถ้ามีแจ้งเตือนที่ไม่ auto-dismiss ค้างอยู่ก่อน นักศึกษาอาจเดินจากไปโดยไม่ทันเห็นตัวนับถอยหลัง
- **ป็อปอัพนับถอยหลังไป Songsue มีหน้าตาของตัวเองแล้ว** — เปลี่ยนจากใช้ไอคอน/หัวข้อเดียวกับป็อปอัพเช็คอินทั่วไป เป็นไอคอนบ้านสีม่วง-น้ำเงิน และหัวข้อ "กำลังไปที่ Songsue" ให้แยกแยะง่ายขึ้นว่ากำลังจะถูกพาไปหน้าอื่น

## ฝั่งทีม (technical changelog)

### QR token ข้ามแอประหว่าง ActiveCAMT ↔ Songsue + endpoint ใหม่สำหรับฝั่ง Songsue ดึงโปรไฟล์ (PR #210)

- **สิทธิ์เข้าถึง / Integrations:** QR token ตอนนี้เป็นสองส่วนต่อกัน — token เดิม (เซ็นด้วย `AUTH_SECRET`, ผูกกับ userId) บวก companion token ใหม่ (เซ็นด้วย secret แยกต่างหาก `ACTIVECAMT_SYNC_SECRET`, ผูกกับ email) ที่แอปพี่น้องอย่าง Songsue ตรวจสอบได้เองโดยไม่ต้องรู้ `AUTH_SECRET` ของ ActiveCAMT เลย — เจตนาแยก secret ชัดเจน ไม่ปนกัน
- เครื่องสแกนฝั่ง ActiveCAMT ตอนนี้ตรวจ token เดิมก่อน ถ้าไม่เจอ fallback ไปตรวจ companion token แทน ถ้าเจอ email ที่ยังไม่มีบัญชีในระบบ จะไปดึงโปรไฟล์จาก Songsue มาสร้างบัญชีให้อัตโนมัติ (reuse upsert logic เดิมที่ใช้ sync ปกติอยู่แล้ว)
- เพิ่ม `GET /api/integrations/songsue/profile` ให้ฝั่ง Songsue เรียกกลับมาในทิศตรงข้าม (กรณีเครื่องสแกน Songsue เจอ QR ที่ออกจาก ActiveCAMT) — endpoint นี้รับ **token ที่สแกนได้จริง ไม่ใช่แค่ email เปล่า ๆ** แล้วตรวจสอบลายเซ็นเองอีกที ป้องกันไม่ให้ใครก็ตามที่มี shared secret ไล่ดึงข้อมูลสุขภาพของใครก็ได้ตามอีเมลที่เดา (แก้จาก draft แรกหลังพบจาก `pdpa-access-guard` review)
- **PDPA:** ทุกครั้งที่ endpoint ใหม่นี้ส่งข้อมูลสุขภาพ/ผู้ติดต่อฉุกเฉินกลับไป จะเขียน audit log บันทึกชื่อ field ที่ส่ง (ไม่บันทึกค่าจริง) — ให้ตรงตามกฎ "การอ่านข้อมูลสุขภาพต้องมี audit log ทุกครั้ง" เหมือน sync ทิศทางอื่น ๆ ที่มีอยู่แล้ว
- **Docker/deploy:** `NEXT_PUBLIC_SONGSUE_DASHBOARD_URL` ต้องฝังตอน build image (ไม่ใช่ runtime env) เพิ่ม build-arg ใน `Dockerfile` และ GitHub Actions workflow ให้ดึงจาก repo variable — ถ้าไม่ตั้งไว้ ฟีเจอร์ redirect ไป Songsue จะปิดเงียบ ๆ (fallback เป็นข้อความเช็คอินสำเร็จปกติ)
- ตรวจสอบด้วย `npm run lint`, `npm run build`, `npm test` (122 ผ่านหมด) และรัน `pdpa-access-guard` reviewer ก่อนเปิด PR — พบ 2 จุด crucial (ไม่มี audit log, email lookup ไม่ผูกกับการสแกนจริง) แก้ครบก่อน merge
- ตัดแพ็กเกจนี้เป็น **tag/release v1.14.0**

### ป็อปอัพเช็คอิน Songsue แยกดีไซน์ของตัวเอง (PR #211)

- **Mobile/UI:** เช็คอินที่เชื่อมกับ Songsue (`songsueLinked`) ตอนนี้ขึ้นป็อปอัพ "Heading to Songsue" แยกต่างหาก (ไอคอนบ้าน สีม่วง-น้ำเงิน หัวข้อของตัวเอง) แทนที่จะยืมไอคอน/หัวข้อจากการ์ดเช็คอินทั่วไป แล้วให้แค่ข้อความในเนื้อหาอธิบายว่าเดี๋ยวจะพาไปหน้าอื่น

- ตรวจสอบด้วย `npm run lint`, `npm run build`
