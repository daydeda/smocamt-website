---

- ไม่มีการเปลี่ยนแปลงที่เห็นได้จากหน้าจอ รอบนี้เป็นการปรับโครงสร้างโค้ดภายในเพื่อให้แก้ไขและดูแลระบบได้ง่ายขึ้น ทุกหน้าทำงานเหมือนเดิม

---

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

---

## ฝั่งทีม (technical changelog)

- **Refactor:** แยกหน้าใหญ่ (events, dashboard, scanner, shop, form builder) เป็น state hook กับ section components ไม่มีการเปลี่ยนพฤติกรรม

- **ไม่มีการเปลี่ยน DB schema หรือ migration**
- **ตรวจสอบแล้ว:** `npm run build`, `tsc`, `npm run lint` (ไม่มี error ใหม่) และ `vitest` 411 tests ผ่าน; ทดสอบหน้าหลักบนเบราว์เซอร์กับฐานข้อมูลทดสอบ

# ActiveCAMT v2.27.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- สินค้าบางรายการในร้านค้ามี "ราคาสวัสดิการ" สำหรับบทบาทที่ได้รับสิทธิ์ เช่น สโมฯ ผู้ที่มีสิทธิ์จะเห็นราคาสวัสดิการ พร้อมราคาปกติขีดฆ่าไว้ และถูกคิดราคาสวัสดิการตอนสั่งซื้อ ผู้ใช้ที่ไม่มีบทบาทนั้นจะเห็นราคาปกติเหมือนเดิม

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- ในฟอร์มสินค้าหน้าร้านค้า มีส่วนใหม่ "สวัสดิการ (ราคาพิเศษเฉพาะบทบาท)" ให้กรอกราคาสวัสดิการและเลือกบทบาทที่ได้รับสิทธิ์ได้ ถ้าเว้นราคาว่างหรือไม่เลือกบทบาท สินค้านั้นจะไม่มีสวัสดิการ รายการสินค้าจะแสดงราคาสวัสดิการและบทบาทที่เกี่ยวข้อง

## ฝั่งทีม (technical changelog)

- **Schema / migration:** เพิ่ม `shop_products.welfare_price`, `shop_products.welfare_roles` และ `shop_orders.welfare_applied` ผ่าน migration 101 (เพิ่มคอลัมน์แบบ additive และ idempotent ไม่มีการลบข้อมูล) ต้องรัน `npm run db:migrate:container` บน prod ก่อน deploy
- **ราคา:** ตัดสินราคาจากบทบาทใน DB ฝั่ง server (`src/lib/shop/shop-welfare.ts`) ไม่เชื่อค่าจาก client ทั้ง checkout และการแก้ไขออเดอร์ของแอดมิน ส่วนลดแบบ bundle คำนวณจากราคาสวัสดิการด้วย
- **Data exposure:** `GET /api/shop` ส่งราคาสวัสดิการให้เฉพาะผู้ที่มีบทบาทที่เลือกไว้ ผู้ใช้อื่นไม่ได้รับข้อมูลนี้
- **ยังไม่ได้ทดสอบ:** ยังไม่ได้ทดสอบ end-to-end ด้วยบัญชีจริงที่มีบทบาทสวัสดิการ
- **ตรวจสอบแล้ว:** `npm run build` ผ่าน, `npm run lint` ไม่มี error ใหม่ (มี error เดิมใน `battle-flow.test.ts`), `vitest` ของ `src/lib/shop` ผ่าน 99 tests

---

อัปเดตรอบนี้ push ตรงเข้า `main` โดยไม่เปิด PR (commit `ea870c6`) ตัดแพ็กเกจเป็น **tag/release v2.27.0** สรุปวันที่ 22 ต.ค. 69

# ActiveCAMT v2.28.0 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- ราคาสวัสดิการในร้านค้าแยกตามตัวเลือกได้แล้ว เช่น ตัวเลือกที่ 1 ปกติ 39 บาท สวัสดิการ 29 บาท และตัวเลือกที่ 2 ปกติ 89 บาท สวัสดิการ 69 บาท ผู้ที่มีสิทธิ์จะเห็นราคาสวัสดิการของแต่ละตัวเลือก พร้อมช่วงราคาปกติขีดฆ่าไว้ ผู้ใช้ที่ไม่มีสิทธิ์เห็นราคาปกติเหมือนเดิม

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- ในฟอร์มสินค้า เมื่อเลือกบทบาทที่ได้รับสวัสดิการแล้ว จะมีช่อง "สวัสดิการ ฿" ในแต่ละแถวของตัวเลือก ให้ตั้งราคาสวัสดิการแยกกันได้ ตัวเลือกที่เว้นว่างไว้จะไม่มีสวัสดิการ และราคาสวัสดิการต้องต่ำกว่าราคาปกติของตัวเลือกนั้น
- สินค้าที่เคยตั้งราคาสวัสดิการแบบเดิม (ราคาเดียวทั้งสินค้า) จะแสดงเป็นราคาของแต่ละตัวเลือกให้โดยอัตโนมัติ

## ฝั่งทีม (technical changelog)

- **Schema / migration:** เพิ่ม `shop_variants.welfare_price` ผ่าน migration 102 (เพิ่มคอลัมน์แบบ additive และ idempotent ไม่มีการลบข้อมูล) ต้องรัน `npm run db:migrate:container` บน prod ก่อน deploy
- **ราคา:** server คำนวณราคาต่อหน่วยของแต่ละตัวเลือกจากบทบาทใน DB (`src/lib/shop/shop-welfare.ts`) ทั้ง checkout และการแก้ไขออเดอร์ของแอดมิน ส่วนลดแบบ bundle คำนวณจากราคาของผู้ซื้อรายนั้น และออเดอร์ที่เคยคิดราคาสวัสดิการจะคงราคาสวัสดิการไว้ตอนแก้ไข
- **Data exposure:** `GET /api/shop` ส่งราคาสวัสดิการเฉพาะผู้ที่มีบทบาทที่เลือกไว้ ผู้ใช้อื่นไม่ได้รับข้อมูลนี้
- **ยังไม่ได้ทดสอบ:** ยังไม่ได้ทดสอบ end-to-end ด้วยบัญชีจริงที่มีบทบาทสวัสดิการ
- **ตรวจสอบแล้ว:** `npm run build` ผ่าน, `npm run lint` ไม่มี error ใหม่, `vitest` ของ `src/lib/shop` ผ่าน 102 tests

# ActiveCAMT v2.28.1 🎉

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- รายการสินค้าในหน้าร้านค้าอ่านง่ายขึ้น สินค้าที่ชื่อยาวหรือมีตัวเลือกเยอะจะไม่ทำให้คอลัมน์ข้อความถูกบีบจนแคบอีกแล้ว ปุ่มต่าง ๆ จะขึ้นบรรทัดใหม่แทนเมื่อพื้นที่ไม่พอ
- ตัวเลือกของสินค้าแสดงเป็นป้ายเล็ก ๆ พร้อมสต็อกคงเหลือ ชื่อตัวเลือกที่ยาวมากจะถูกตัดและดูชื่อเต็มได้โดยวางเมาส์ไว้ ถ้ามีมากกว่า 6 ตัวเลือก จะซ่อนส่วนที่เหลือไว้ใต้ปุ่ม "+N ตัวเลือก"

## ฝั่งทีม (technical changelog)

- **Mobile/UI:** การ์ดสินค้าใน `ProductsTab.tsx` ใช้ `flex-wrap` และรวมปุ่ม action ไว้เป็นกลุ่มเดียว เพิ่ม component `VariantChips` สำหรับแสดงตัวเลือกแบบย่อ/ขยายได้
- **ไม่มีการเปลี่ยน DB schema หรือ migration** และไม่กระทบ PDPA หรือสิทธิ์เข้าถึง
- **ตรวจสอบแล้ว:** `tsc` และ `eslint` ไม่มี error ใหม่ ยังไม่ได้รัน `npm run build` เต็มรูปแบบ เพราะติดตั้งแพ็กเกจ `xlsx` ในสภาพแวดล้อมนี้ไม่ได้
