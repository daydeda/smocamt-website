## 👋 ActiveCAMT คืออะไร

ActiveCAMT คือแพลตฟอร์มกิจกรรมนักศึกษาของ **วิทยาลัยศิลปะ สื่อ และเทคโนโลยี (CAMT) มหาวิทยาลัยเชียงใหม่** ที่เข้ามาแทนที่กระดาษเซ็นชื่อด้วยการ **เช็คอินผ่าน QR** ที่รวดเร็วและปลอมแปลงยาก และเปลี่ยนการเข้าร่วมกิจกรรมให้เป็นการแข่งขันฉันมิตรระหว่าง **บ้าน (House)** ของวิทยาลัย ผ่านกระดานคะแนนบ้านแบบสด

นักศึกษาดูและลงทะเบียนกิจกรรม แสดง QR ที่หน้างาน แล้วเฝ้าดูบ้านของตัวเองไต่อันดับ ส่วนทีมงานจัดกิจกรรม สแกนเช็คชื่อ เก็บแบบประเมิน และดูแลร้านค้าได้ในที่เดียว โดยถือว่าการคุ้มครองข้อมูลส่วนบุคคล ([PDPA](https://pdpc.or.th/)) เป็นข้อบังคับ ไม่ใช่ส่วนเสริมที่ค่อยทำทีหลัง

> [!NOTE]
> ระบบเข้าสู่ระบบด้วย Google OAuth การจำกัดเฉพาะอีเมล `@cmu.ac.th` ยังรอ CMU IT เปิดให้ ปัจจุบันจึงใช้บัญชี Google ใดก็ได้ การล็อกอินจึงหมายถึง "มีบัญชี" ไม่ได้ยืนยันว่าเป็นนักศึกษา CMU

### 🔐 ความเป็นส่วนตัวและความปลอดภัย

- **ควบคุมสิทธิ์หลายชั้น** บทบาท (`student`, `smo`, `anusmo`, `registration`, `organizer`, `admin`, `super_admin` รวมถึงประธานชมรม/สาขาและผู้ขายในร้านค้า) ถูกตรวจทั้งที่ edge proxy, เลย์เอาต์แอดมิน *และ* ทุก API route ไม่เคยพึ่งแค่หน้า UI
- **ข้อมูลสุขภาพเปิดเท่าที่จำเป็น** ฝ่ายทะเบียนเห็นแค่ *สัญญาณ* ว่านักศึกษามีโรคประจำตัว ส่วนรายละเอียดเปิดให้แอดมิน และประธานชมรม/สาขาเฉพาะสมาชิกหรือกิจกรรมของตน โดยซ่อนชื่อผู้ติดต่อฉุกเฉิน
- **Audit log แบบเพิ่มได้อย่างเดียว** ทุกครั้งที่เข้าถึงข้อมูลอ่อนไหวจะถูกบันทึกในล็อกแบบ hash-chain
- **จำกัดการอัปโหลด** รูปไม่เกิน 5 MB ทั้งฝั่งไคลเอนต์และเซิร์ฟเวอร์ และสลิปการโอนเก็บใน bucket ส่วนตัวที่ต้องยืนยันตัวตนก่อนเข้าถึง

## 🧰 เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| เฟรมเวิร์ก | Next.js 16 (App Router), React 19, TypeScript 5 |
| สไตล์ | Tailwind CSS v4 (ตั้งค่าใน `globals.css`), Framer Motion |
| การยืนยันตัวตน | NextAuth v5 (beta) + `@auth/drizzle-adapter`, Google OAuth |
| ฐานข้อมูล | PostgreSQL + Drizzle ORM และ migration ด้วย `drizzle-kit` |
| ฟอร์มและการตรวจสอบ | React Hook Form, Zod v4 |
| QR | `html5-qrcode` / `jsqr` (สแกน), `qrcode.react` (สร้าง) |
| การทดสอบ | Vitest (เฉพาะ pure logic: สิทธิ์ QR token audit chain และเกม) |
| การ Deploy | Docker + Postgres บนเซิร์ฟเวอร์มหาวิทยาลัย จัดการด้วย Portainer |

## 🚀 เริ่มต้นใช้งาน

**สิ่งที่ต้องมี:** Node.js 20+, npm และ Docker (สำหรับ Postgres บนเครื่อง)

```bash
# 1. ติดตั้งแพ็กเกจ
npm install

# 2. สร้างไฟล์ environment แล้วกรอกค่า
cp .env.production.example .env

# 3. สร้างสคีมา และ (ถ้าต้องการ) ใส่ข้อมูลตัวอย่าง
npm run db:push        # ใช้ตอนพัฒนาเท่านั้น ส่วน deploy จริงใช้ db:migrate
npm run db:seed

# 4. รันเซิร์ฟเวอร์พัฒนาที่ http://localhost:3000
npm run dev
```

ตัวแปรหลักใน `.env`:

```env
DATABASE_URL="postgresql://user:password@localhost:5432/activecamt"
AUTH_SECRET="a-long-random-string"
AUTH_URL="http://localhost:3000/api/auth"
AUTH_GOOGLE_ID="your-google-oauth-client-id"
AUTH_GOOGLE_SECRET="your-google-oauth-client-secret"
```

> [!TIP]
> ไฟล์ [`.env.production.example`](./.env.production.example) อธิบายวิธีขอค่าแต่ละตัว รวมถึง Google OAuth client บน Windows ใช้ `./run-local.ps1` เพื่อสร้าง `.env` เปิด Postgres ใน Docker และรันแอปให้อัตโนมัติได้

### คำสั่งที่ใช้บ่อย

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm run dev` | เซิร์ฟเวอร์พัฒนา พอร์ต 3000 |
| `npm run lint` | ตรวจโค้ดด้วย ESLint |
| `npm test` | Vitest (เฉพาะ pure logic) |
| `npm run build` / `npm start` | Build และรันโหมดโปรดักชัน |
| `npm run db:generate` | สร้าง SQL migration จาก `src/db/schema.ts` |
| `npm run db:migrate` | รัน migration กับฐานข้อมูลใน `.env` |
| `npm run db:studio` | ดูข้อมูลด้วย Drizzle Studio |

## 🐳 การ Deploy

โปรดักชันรันเป็น Docker stack (แอป + Postgres) บนเซิร์ฟเวอร์มหาวิทยาลัย จัดการผ่าน Portainer ส่วนบนเครื่องตัวเองยกทั้งระบบขึ้นได้ด้วย:

```bash
docker-compose up -d --build
```

รายละเอียดการตั้งค่าเซิร์ฟเวอร์ดูที่ [`docker-stack.yml`](./docker-stack.yml), [`university_server_deployment_guide.md`](./university_server_deployment_guide.md) และ [`production_deployment_architecture.md`](./production_deployment_architecture.md)

> [!WARNING]
> ระบบจะไม่ migrate ให้เองตอนคอนเทนเนอร์เริ่มทำงาน ให้รัน `npm run db:migrate:container` จากคอนโซล Portainer ของคอนเทนเนอร์แอป **ก่อน** deploy โค้ดที่อ่านคอลัมน์ใหม่หรือที่เปลี่ยนไป และ migration ต้องรันซ้ำได้ (idempotent) และห้ามทำลายข้อมูล

## 🗂️ โครงสร้างโปรเจกต์

```text
src/
├─ app/          เส้นทางของ Next.js: dashboard/, battle/, admin/, api/ ...
├─ modules/      ตรรกะตามโดเมน (events, houses, clubs, audit, ...)
├─ lib/          เงื่อนไขสิทธิ์ การเซ็น QR ตัวช่วย PDPA i18n games/
├─ components/   UI ที่ใช้ร่วมกัน (admin/, layout/, home/, ui/)
├─ db/           schema.ts (แหล่งความจริง), migrate, seed, guard
└─ proxy.ts      Edge middleware (ด่านแรกของการควบคุมสิทธิ์)
drizzle/         SQL migration ที่สร้างอัตโนมัติ
docs/            SRS เอกสารออกแบบ เอกสารเกม วิกิ
updates/         บันทึกการอัปเดตรายช่วงเวลา (ภาษาไทย)
```
