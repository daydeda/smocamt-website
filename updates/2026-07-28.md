## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **คนที่ถือตำแหน่ง "ฝ่ายทะเบียน" ในชมรม/สาขา/SMO/ANUSMO สร้างแบบฟอร์มกิจกรรมเองได้แล้ว** — เดิมถึงระบบฝั่งหลังบ้านจะอนุญาตอยู่แล้ว แต่หน้าจอไม่เคยเปิดปุ่ม "สร้างแบบฟอร์ม" ให้เห็นเลย ตอนนี้คนที่ถือตำแหน่งนี้ (ไม่ใช่ role "ฝ่ายทะเบียน" แต่เป็นตำแหน่งในชมรม/สาขา/SMO/ANUSMO) สร้าง-แก้ไขแบบฟอร์มของกิจกรรมที่ตัวเองดูแลได้เอง (แบบฟอร์มจะรออนุมัติจากสตาฟก่อน เหมือนเคสของประธานชมรม/สาขา)
- **ฝ่ายทะเบียน/ผู้จัดกิจกรรม (organizer) ส่งออกไฟล์ Excel รายชื่อผู้เข้าร่วมกิจกรรมได้แล้ว** — เดิมส่งออกไม่ได้เลย ตอนนี้ส่งออกได้ แต่จะไม่เห็นข้อมูลสุขภาพรายบุคคล (เห็นแค่เบอร์โทรติดต่อ) แทนที่ด้วยสรุปภาพรวม เช่น มีกี่คนที่แจ้งว่ามีโรคประจำตัว/แพ้อาหารในสรุปท้ายไฟล์ (ไม่ระบุชื่อ)
- **เพิ่มตัวกรอง "ตำแหน่ง" ในหน้ารายชื่อสมาชิก (Admin → Students)** — กรองตาม SMO/ANUSMO Position ได้แล้ว

## ฝั่งทีม (technical changelog)

### เปิดสิทธิ์ตำแหน่ง "ฝ่ายทะเบียน" ให้จัดการฟอร์มได้ + เปิด export attendance ให้ registration/organizer (PR #203)

- **สิทธิ์เข้าถึง (access control):** เพิ่ม session flag ใหม่ `hasClubRegistrationPosition` (precompute ใน `src/auth.ts`, mirror pattern เดียวกับ `hasClubPosition` — ต้อง query `club_members` เพราะข้อมูลนี้ไม่เคยอยู่ใน session) รวมกับ `majorPosition`/`smoPosition`/`anusmoPosition` ที่มีอยู่แล้ว ประกอบเป็น `hasRegistrationTitle` ใน `admin/events/page.tsx` และ `EventFormBuilderModal.tsx` — ขยายเฉพาะ `canManageForms` เท่านั้น ไม่แตะสิทธิ์อื่น (แก้ event, ดูข้อมูลการแพทย์, ลบผู้ลงทะเบียน) เพราะ server (`gateEventForms`'s `isPositionScoped`) จำกัด scope ไว้เฉพาะกิจกรรมของชมรม/สาขาตัวเองอยู่แล้ว และบังคับ `reviewStatus: 'pending'` เสมอ
- ระหว่างแก้พบบั๊กเดิมใน `EventFormBuilderModal.tsx` — component นี้คำนวณสิทธิ์ตัวเองแยกจากหน้า page เลย และไม่เคยเช็ค global SMO/ANUSMO registration position เลย ทำให้แม้แต่คนที่ระบบควรอนุญาตอยู่แล้วก็เจอฟอร์มโหมด read-only ทั้งที่ปุ่ม "สร้างฟอร์ม" ในหน้าโชว์ให้กด
- **PDPA:** `api/admin/events/[id]/export` เดิมบล็อก registration/organizer ไม่ให้ export เลย ตอนนี้เปิดให้ export ได้ แต่ไม่มีคอลัมน์ข้อมูลการแพทย์ต่อคนใด ๆ (ไม่มีแม้แต่ Meds Check) และจำกัด contact ให้เห็นแค่เบอร์โทร (ไม่ให้ Email/Contact Channels เพราะฝั่งหน้าจอเดิมก็ไม่เคยให้) แลกกับสรุปภาพรวม "Medical Summary" (นับจำนวนต่อหมวดหมู่ ไม่ระบุชื่อ) ต่อท้ายชีต Summary — ถ้ากิจกรรมมีผู้เข้าร่วมน้อยกว่า 5 คนจะซ่อนสรุปนี้ไปเลยเพื่อกันการเดาตัวบุคคลได้
- แก้บั๊กเดิมอีกจุด: route นี้เช็คสิทธิ์ดูข้อมูลการแพทย์แบบเต็มจาก `super_admin` เท่านั้น ไม่รวม `admin` ธรรมดา ทั้งที่ CLAUDE.md และ route attendance บนหน้าจอให้สิทธิ์ทั้งคู่อยู่แล้ว — แก้ให้ตรงกัน
- ผ่าน internal PDPA/access-control review รอบหนึ่งก่อน merge — พบและแก้เพิ่ม: ตัด Email/Contact Channels ที่หลุดไปให้ registration/organizer โดยไม่ตั้งใจ, เพิ่ม emergency medication เข้าไปในสรุปที่นับ (เดิมนับไม่ครบ), กันเคส multi-role (คนที่ถือทั้ง admin และ registration ไม่ควรถูกจำกัดสิทธิ์ลง), รวม query `club_members` สองอันเป็นอันเดียว
- ตรวจสอบด้วย `npx tsc --noEmit`, `npm run lint` (ไม่มี error ใหม่), `npm run build` (ผ่าน)
- ตัดแพ็กเกจนี้เป็น **tag/release v1.12.0**
