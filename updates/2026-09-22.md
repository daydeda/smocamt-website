## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **SMO ที่ควบตำแหน่งประธานชมรม/สาขาด้วย เห็นข้อมูลกิจกรรมและรางวัลครบทุกรายการเหมือนเดิมแล้ว** ก่อนหน้านี้ถ้าใครมีทั้งสิทธิ์ SMO และเป็นประธานชมรมหรือสาขาไปด้วย ระบบจะพลาดไปจำกัดมุมมองให้เห็นแค่ของชมรม/สาขาตัวเองเท่านั้น ทั้งที่สิทธิ์ SMO ควรเห็นทุกกิจกรรม/รางวัลอยู่แล้ว ตอนนี้แก้ให้การมีตำแหน่งประธานไม่ไปลดทอนสิทธิ์ที่มีอยู่เดิม
- **SMO เปิดดูรายการ "รอรูป" ในหน้าการรับรางวัลได้แล้ว** ก่อนหน้านี้ต้องเป็นแอดมิน/องค์กรเท่านั้นถึงจะกดดูรายชื่อคนที่ยังไม่มีรูปหลักฐานได้ ทั้งที่ SMO เป็นคนแจกรางวัลหน้าบูธอยู่แล้วและมักเป็นคนที่ต้องแนบรูปย้อนหลังเองพอดี ตอนนี้เปิดให้ทำได้เหมือนกัน โดยรายชื่อทั้งหมด (ผู้ชนะ/รายงาน) ยังจำกัดเฉพาะแอดมิน/องค์กรเหมือนเดิม
- **ปุ่มแนบรูปหลักฐานรางวัลบนแอนดรอยด์ถ่ายรูปได้ตรง ๆ แล้ว** ก่อนหน้านี้กดปุ่มแนบรูปบนมือถือแอนดรอยด์จะเปิดคลังภาพให้เลือกอย่างเดียว ต้องออกไปถ่ายรูปแยกแล้วค่อยกลับมาเลือก ตอนนี้แยกเป็นสองปุ่มชัดเจน ถ่ายรูปใหม่ หรือเลือกจากคลังภาพ
- **ข้อความ "มีคนรับของรางวัล/เช็คอินไปแล้ว" ที่ขึ้นมาเองทั้งที่ไม่มีใครสแกน หายไปแล้ว** บางครั้งหลังสแกนเสร็จแล้ว หน้าจอจะขึ้นข้อความเตือนซ้ำแบบไม่มีที่มา ทำให้เจ้าหน้าที่หน้าบูธสับสนว่าเพิ่งสแกนซ้ำไปหรือเปล่า ตอนนี้แก้ให้ไม่ขึ้นข้อความหลอกแบบนี้อีก
- **สแกน QR ทั้งที่เครื่องสแกนเช็คอินและหน้าแจกรางวัลไวขึ้นชัดเจน** แม้จะยื่น QR โค้ดเข้าใกล้กล้องมาก ๆ ก็ยังอ่านติดเร็ว ปรับทั้งความเร็วในการอ่านโค้ดและการโฟกัสภาพให้ดีขึ้น
- **super_admin ลบรางวัลที่สร้างผิดหรือไม่ใช้แล้วได้แล้ว** พร้อมหน้าต่างยืนยันที่บอกชัดเจนว่ารางวัลนี้มีคนรับไปแล้วกี่คนและมีรูปหลักฐานกี่รูป ถ้ามีคนรับไปแล้วต้องพิมพ์ชื่อรางวัลยืนยันก่อนถึงจะลบได้ หรือเลือก "ปิดรับแทนการลบ" ก็ได้ถ้าแค่อยากหยุดแจกแต่ยังเก็บประวัติไว้

## ฝั่งทีม (technical changelog)

### แก้สิทธิ์เข้าถึง แก้ UX รับรางวัล และเร่งความเร็วสแกนเนอร์ (PR #252, merge commit `df014db`)

- **สิทธิ์เข้าถึง:** เพิ่ม `isEventUnscopedStaff` (`src/lib/admin-access.ts`) และตัวเทียบเท่าฝั่งรางวัลใน `src/lib/prize-scope.ts` แทนการเช็ค role list แบบ inline กระจายอยู่หลาย route (`api/admin/events`, `api/admin/scan`, `api/admin/scan/count`, `api/admin/events/[id]/report`, `api/admin/events/[id]/attendance`, `api/admin/prizes`) เพราะของเดิมเช็คแค่ role เดียวแล้วพัง ทำให้คนที่มีทั้ง `smo` และตำแหน่งประธานเห็นข้อมูลแคบลงผิดจากที่ควรเป็น หลักการใหม่คือมีสิทธิ์กว้างอยู่แล้วจากบทบาทไหนก็ไม่ถูกตำแหน่งประธานที่ถืออยู่ด้วยมาลดทอนสิทธิ์นั้นลง ตรวจแล้วว่า route ที่มีกลไก scope ของตัวเองอยู่แล้วถูกต้อง (`api/admin/events/[id]/form` ที่ smo อ่านได้อย่างเดียวห้ามแก้ไข และ `api/admin/appeals` ที่ resolve ต้องไม่ให้ smo ทำ) ไม่ต้องแก้เพิ่ม
- **PDPA:** เขียนใหม่ส่วน ownership-check ของ `api/admin/events/[id]/attendance` เพื่อรองรับเคสที่ smo ถือ tag ประธานด้วยแต่ไม่ได้เป็นเจ้าของกิจกรรมนั้นจริง ให้ตกกลับไปเห็นข้อมูลระดับ thin roster (ไม่ใช่ระดับ president-tier ที่เห็นรายละเอียดการแพทย์) แทนที่จะถูกปฏิเสธหรือหลุดไปเห็นข้อมูลผิดระดับ ให้ agent ตรวจ access-control/PDPA แยกต่างหากยืนยันทั้งสองเคส (กิจกรรมที่เป็นเจ้าของและไม่ได้เป็นเจ้าของ) และยืนยันว่า audit log บันทึกถูกระดับ
- **Feature (รอรูป):** `GET /api/admin/prizes/[id]/awaiting-photo` เปลี่ยน gate จาก `canManage` เป็น `canAward` (สอดคล้องกับ `docs/features/prize-claim.md`) และเพิ่ม audit log เมื่อเปิดดูโดยสิทธิ์ที่ไม่ใช่ `canManage`
- **UI (กล้องแอนดรอยด์):** แยกปุ่มแนบรูปในทั้ง `PrizeAwardPanel.tsx` และ dialog "รอรูป" ของ `PrizesClient.tsx` เป็นปุ่มกล้อง (`capture="environment"`) กับปุ่มคลังภาพแยกกัน จากเดิมที่มีปุ่มเดียวเปิดคลังภาพอย่างเดียวบนแอนดรอยด์
- **Bug (ข้อความหลอก):** เพิ่ม cooldown map ตามเวลาต่อ token ทั้งใน `PrizeAwardPanel.tsx` และ `admin/scanner/page.tsx` แยกออกจาก in-flight guard เดิม เพราะ guard เดิมอย่างเดียวยังมีช่องที่ผลลัพธ์เก่าเด้งกลับมาแสดงซ้ำได้ ตัดสินใจไม่ทำตามแผนเดิมที่จะหยุด clear `lastTokenRef` ตอนปิดหน้าต่าง เพราะจะบล็อกการสแกนโค้ดเดิมซ้ำหลัง error เน็ตชั่วคราวไปตลอดทั้ง session ซึ่งเป็นบั๊กใหม่ที่แย่กว่าเดิม
- **Perf (สแกนเนอร์):** เพิ่ม `src/lib/qr-scanner-config.ts` รวม config ของ `html5-qrcode` ที่ใช้ร่วมกันทั้งสองจุด จำกัด `formatsToSupport` ให้อ่านแค่ QR (จากเดิมที่ไล่ตรวจทั้ง 17 รูปแบบทุกเฟรม) ปรับกรอบสแกนให้ขนาดอิงตามวิวไฟน์เดอร์จริง ปิด mirrored re-decode pass ที่ไม่จำเป็นสำหรับ QR โค้ด และเปิด continuous autofocus แก้ปัญหาโค้ดที่ยื่นใกล้กล้องแล้วภาพเบลอ ตรวจ source ของ library จริงยืนยันว่า option ไหนต้องส่งตอนสร้าง instance กับตอน `start()` เพราะสองจุดนี้ config คนละรูปแบบกัน ส่งผิดจุดแล้วเงียบไม่มี error แต่ไม่มีผลอะไรเลย และปรับหน้าสแกนเนอร์ให้ไม่ restart กล้องทุกครั้งที่ resize เล็กน้อย restart เฉพาะตอนความกว้างเปลี่ยนมากจริง ๆ หรือหมุนจอเท่านั้น
- **Feature (ลบรางวัล):** เพิ่มปุ่มลบ (super_admin เท่านั้น) พร้อม `DeletePrizeDialog` ใหม่ใน `PrizesClient.tsx` แสดงจำนวน claim/รูปก่อนลบ บังคับพิมพ์ชื่อรางวัลยืนยันถ้ามี claim แล้ว และมีทางเลือก "ปิดรับแทนการลบ" DELETE route เดิม (`api/admin/prizes/[id]`) ลบรูปหลักฐานที่ถูก orphan ออกจาก storage ด้วย เพิ่มนับจำนวนรูปที่ลบไม่สำเร็จเข้าไปใน audit log line เพื่อให้เห็นใน `/admin/audit-logs` แทนที่จะหลุดหายไปแค่ใน container log
- **UI (QR ขนาดใหญ่ขึ้น):** เพิ่มขนาด QR canvas และลด error-correction level (`H` → `M`) ที่ `dashboard/id/page.tsx` และ `DashboardClient.tsx` เพื่อให้ตัวโมดูล QR แต่ละช่องใหญ่ขึ้น อ่านง่ายขึ้นบนมือถือจอเล็ก
- **i18n:** เพิ่ม/แก้ key ใหม่ครบทั้ง EN/TH/MM/CN ใน `src/lib/i18n.ts` (ปุ่มกล้อง/คลังภาพแยกกัน ข้อความ "รอรูป" สำหรับ award-only role ข้อความชุดหน้าต่างลบรางวัลทั้งหมด) ให้ agent ตรวจความครบถ้วนแยกต่างหาก
- ให้ agent ตรวจ UI/UX แยกต่างหากเจอจุดที่ `DeletePrizeDialog.doDelete()` อาจโชว์ข้อความ error ดิบจาก server เป็นภาษาอังกฤษให้แอดมิน TH/MM/CN เห็นตอน race condition แก้แล้วให้ throw ข้อความแปลคงที่เหมือน sibling function ข้างเคียงเสมอ

# ActiveCAMT v2.12.1 🎉

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **หน้าต่างแจกรางวัลไม่ล้นจอมือถือจอเตี้ยหรือแนวนอนแล้ว** ก่อนหน้านี้ถ้าเปิดหน้าต่างแจกรางวัลบนมือถือที่หมุนเป็นแนวนอนหรือจอเตี้ย ปุ่มยืนยันด้านล่างอาจโดนกรอบกล้องดันจนล้นออกนอกจอ กดไม่ถึง ตอนนี้ปรับให้กรอบกล้องหดตามพื้นที่จอที่เหลือ ปุ่มยืนยันกดถึงเสมอ และหน้าต่างไม่ไปทับพื้นที่ขอบจอ (เช่น รอยบากหรือแถบนำทางด้านล่าง) บนมือถือรุ่นใหม่ด้วย
- **กรอบเล็งสแกนในหน้าแจกรางวัลเห็นชัดขึ้น** เพิ่มกรอบสี่เหลี่ยมสีขาวให้เล็งง่ายขึ้นตอนยื่น QR โค้ดเข้ากล้อง

## ฝั่งทีม (technical changelog)

### ปรับหน้าต่างแจกรางวัลให้ responsive และรองรับ safe area (PR #253, merge commit `e76ed0d`)

- **UI (responsive):** ย้าย inline style ของ `PrizeAwardPanel.tsx` ทั้งหมดไปเป็น CSS module (`PrizeAwardPanel.module.css`) เปลี่ยนความสูงสูงสุดจาก `92vh` คงที่เป็น clamp แบบอิง `dvh` พร้อม padding แบบ `env(safe-area-inset-*)` แทน และเพิ่ม media query `max-height: 500px` ให้กรอบกล้องหดลงอีกชั้นบนจอแนวนอน กันปุ่มยืนยันหลุดออกนอกจอ
- **Bug (กล้อง iOS):** วิดีโอที่ `html5-qrcode` แทรกเข้ามาไม่มีการบังคับสัดส่วน ถ้ากล้องส่งภาพแนวตั้งมา (บางรุ่นไม่ทำตาม aspectRatio ที่ขอ) วิดีโอจะล้นออกนอกกรอบสี่เหลี่ยมจัตุรัส แก้โดยบังคับ `object-fit: cover` ให้วิดีโอเสมอ และซ่อน element `#qr-shaded-region` ที่ library แทรกมาเองซึ่งไม่ได้ใช้ในดีไซน์นี้
- **A11y:** เพิ่ม `role="dialog"`, `aria-modal`, `aria-labelledby` ให้หน้าต่างสำหรับโปรแกรมอ่านหน้าจอ และเพิ่มกรอบเล็งสแกน (`scanGuide`) ที่มองเห็นได้จริงแทนที่จะมีแค่กรอบกล้องเฉย ๆ
- ไม่มีการแก้ logic การสแกน/แจกรางวัลเลย เป็นการแก้ layout/CSS และ a11y attribute เท่านั้น
- ตรวจสอบแล้วด้วย `npx eslint`, `npx tsc --noEmit`, `npm run build` ผ่านครบ

# ActiveCAMT v2.12.2 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **ปัญหาแนบสลิปโอนเงินในหน้าร้านค้าแล้วขึ้น "Internal Server Error" ตอนนี้แก้แล้วบางส่วน** ถ้าเจออีกครั้งจะขึ้นข้อความที่ชัดเจนขึ้นแทน ("อ่านไฟล์ที่แนบไม่สำเร็จ กรุณาตรวจสอบสัญญาณอินเทอร์เน็ตแล้วลองใหม่") และทีมงานจะมีข้อมูลพอสืบต่อได้ว่าทำไมถึงอ่านไฟล์ไม่สำเร็จ

## ฝั่งทีม (technical changelog)

### วินิจฉัย FormData parse error บนหน้าแนบสลิปร้านค้าและอัปโหลดรูปโปสเตอร์ (PR #254, merge commit `4908de9`)

- **Bug:** นักศึกษารายงานว่าแนบสลิปโอนเงินในหน้าร้านค้า (`/dashboard/shop`) แล้วขึ้น "Internal Server Error" แบบไม่มีรายละเอียด ตรวจแล้วพบว่าเป็นบั๊กสายเดียวกับที่เคยวินิจฉัยและแก้ไปแล้วใน `a0194f7` สำหรับ `/api/forms/upload` คือ reverse proxy ของ CAMT บางครั้ง mangle multipart body ก่อนที่ Next.js จะ parse ได้ ทำให้ `req.formData()` throw `TypeError: Failed to parse body as FormData` ก่อนโค้ดฝั่งแอปจะได้ทำงานเลย (ก่อน `hardenImageUpload`/storage) แต่ตอนนั้นแก้แค่ route เดียว ส่วน `/api/shop/slip` และ `/api/upload` (รูปโปสเตอร์/avatar) ยังไม่ได้แก้ตาม เลยตกไปอยู่ใน catch-all เดิมที่คืนข้อความทั่วไปไม่มีรายละเอียด
- **Fix:** ห่อ `req.formData()` ด้วย try/catch แยกต่างหากในทั้งสอง route เหมือนที่ `/api/forms/upload` ทำไว้ ถ้า parse ไม่สำเร็จจะ log header ที่ Next เห็นจริง (`content-type`, `content-length`, `user-agent`, `referer`) ไว้ใน container log และคืนข้อความเฉพาะเจาะจงแทนข้อความทั่วไป เพื่อให้ครั้งหน้าถ้าเกิดซ้ำ ทีมงานเช็ค log ใน Portainer แล้วยืนยันสมมติฐาน reverse proxy ได้จริง แทนที่จะต้องเดาอีกรอบ
- ไม่ได้แก้ business logic ของการอัปโหลด/ตรวจสลิปเลย เป็นการเพิ่ม error handling และ logging เท่านั้น
- ตรวจสอบแล้วด้วย `npx eslint`, `npx tsc --noEmit`, `npm run build` ผ่านครบ (warning/error ที่เจอเป็นของเดิมในไฟล์ที่ไม่เกี่ยวข้อง)

# ActiveCAMT v2.12.3 🎉

## ฝั่งนักศึกษา (สิ่งที่ user จะเห็น)

- **แนบสลิปโอนเงินในหน้าร้านค้าแล้วขึ้น "Internal Server Error" แบบไม่มีคำอธิบาย ตอนนี้แก้ต้นตอเพิ่มอีกขั้นแล้ว** มีนักศึกษารายงานว่าลองแนบไฟล์ .JPEG ธรรมดาแล้วยังเจอปัญหานี้อยู่ ตรวจสอบแล้วพบว่าไม่เกี่ยวกับชนิดไฟล์เลย แต่เป็นเพราะระบบเขียนไฟล์ลงเซิร์ฟเวอร์ไม่สำเร็จแล้วไม่บอกรายละเอียดอะไรเลย ตอนนี้ถ้าเกิดปัญหานี้อีก ทีมงานจะเห็นสาเหตุจริงในระบบและตามแก้ได้ทันที

## ฝั่งทีม (technical changelog)

### เผยข้อความ error จริงจากการเขียนไฟล์สลิปและรูปโปสเตอร์ลงดิสก์ (PR #255, merge commit `9c45098`)

- **Bug:** จากการตรวจสอบเพิ่มเติมหลัง PR #254 พบว่านักศึกษายังเจอ "Internal Server Error" ตอนแนบสลิป .JPEG ธรรมดา (ไม่ใช่ HEIC ที่มีข้อความแจ้งเตือนเฉพาะอยู่แล้ว) ตรวจโค้ดแล้วพบว่า `uploadSlip()` ใน `src/lib/shop-storage.ts` (เส้นทางที่ใช้งานจริงบน self-hosted deploy เพราะตั้งใจไม่ตั้งค่า `SUPABASE_*` ไว้ ตาม `docker-stack.yml`) เรียก `mkdir`/`writeFile` โดยไม่มี try/catch เลย ถ้าเขียนไฟล์ไม่สำเร็จ (เช่น permission ของ volume `.uploads-private` ที่อาจตกค้างมาจากก่อนที่ Dockerfile จะเพิ่ม `chown` ให้) จะได้ error ดิบที่ไม่ใช่ `ImageValidationError` เลยตกไปอยู่ใน catch ทั่วไปที่คืนข้อความ "Internal Server Error" แบบไม่มีรายละเอียดอะไรเลย และพบช่องโหว่แบบเดียวกันใน `/api/upload` (รูปโปสเตอร์/avatar) ที่ซ้ำร้ายกว่าคือ `mkdir` ที่ล้มเหลวถูกกลืนเงียบด้วย `catch(e){}` เปล่า ๆ ก่อนจะไปเจอ `writeFile` ที่ไม่มีการดักจับเลยเหมือนกัน
- **Fix:** อ้างอิงแพทเทิร์นที่ `src/lib/form-file-storage.ts` (อัปโหลดไฟล์แบบฟอร์ม) เคยแก้ปัญหาสายเดียวกันไปแล้วด้วย `StorageError` ที่พกข้อความ error จริงจากระบบไฟล์ติดไปด้วย นำมาใช้กับ `shop-storage.ts` โดยเพิ่ม `StorageError` และห่อการเขียนไฟล์ด้วย try/catch แล้วให้ route `/api/shop/slip` ดักจับ `StorageError` คืนข้อความจริงกลับไป (แบบเดียวกับที่ `/api/forms/upload` ทำอยู่แล้ว) และห่อการเขียนไฟล์ของ `/api/upload` ด้วยวิธีเดียวกัน
- ไม่ได้แก้ business logic ของการอัปโหลด/ตรวจสลิปเลย เป็นการเพิ่ม error handling และ logging เท่านั้น เหมือนกับ PR #254
- ตรวจสอบแล้วด้วย `npx eslint`, `npx tsc --noEmit`, `npm run build` ผ่านครบ (warning ที่เจอเป็นของเดิมในไฟล์ที่ไม่เกี่ยวข้อง)
