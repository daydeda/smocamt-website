# ActiveCAMT v2.21.0 🎉

# อัปเดต ActiveCAMT ประจำวันที่ 16 ต.ค. 69

สรุปสำหรับวันที่ 16 ต.ค. 69 เอาไว้ลง Discord และให้ทีมที่เกี่ยวข้องอ่านกัน

---

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **ดูคำสั่งซื้อและสลิปแยกทีละสินค้าได้แล้ว** ในหน้าจัดการร้านค้า แต่ละสินค้ามีปุ่ม "คำสั่งซื้อ" ที่พาไปหน้าเฉพาะของสินค้านั้น ทำให้ตรวจสลิปและส่งมอบของทีละสินค้าได้สะดวกขึ้นโดยไม่ต้องกรองหาเอง
- **ค้นหาคำสั่งซื้อด้วยชื่อหรือรหัสนักศึกษาได้** ช่องค้นหาในแท็บคำสั่งซื้อรองรับชื่อ ชื่อเล่น รหัสนักศึกษา และชื่อผู้รับของ ใช้ร่วมกับตัวกรองอื่นได้
- **ตัวกรองวันที่ใช้ง่ายขึ้น** เลือกช่วงวันที่ได้ตรงๆ ตั้งแต่วันถึงวัน (รวมทั้งวันสุดท้ายทั้งวัน) และมีปุ่มลัด วันนี้ 7 วัน และ 30 วัน
- **ไปยังหน้าที่ต้องการได้ทันที** ทั้งรายการสินค้าและคำสั่งซื้อมีปุ่มหน้าแรกและหน้าสุดท้าย และพิมพ์เลขหน้าลงในช่องแล้วกด Enter เพื่อไปหน้านั้นได้เลย
- ผู้ขายและประธานชมรม/สาขาเข้าหน้าสินค้าของตัวเองได้ตามสิทธิ์เดิม ไม่เห็นคำสั่งซื้อของทีมอื่น

---

## ฝั่งทีม (technical changelog)

### หน้าคำสั่งซื้อรายสินค้า และการปรับปรุงหน้าจัดการร้านค้า (PR #273, merge commit `6bb36cb`)

- **Access control:** เพิ่ม `src/app/admin/shop/[productId]/` (หน้า server ที่ gate ด้วย `isShopManager` และ client component ที่ใช้ `OrdersTab` ร่วมกับ `/admin/shop`) ขอบเขตข้อมูลยังมาจาก `/api/admin/shop/orders` และ `/api/admin/shop/products/[id]/orders` ที่ scope ฝั่ง server เหมือนเดิม
- **`src/lib/admin-access.ts`:** `isScannerOnlyAllowedPath` อนุญาตเฉพาะ path ระดับเดียว `/admin/shop/<id>` สำหรับ role ที่ถูกจำกัดให้อยู่ในร้านค้า มี test ใน `admin-access.test.ts` ครอบคลุมทั้งกรณีที่อนุญาตและไม่อนุญาต
- **UI:** ค้นหาจากชื่อ ชื่อเล่น student ID และ recipient name ใน `OrdersTab`, ตัวกรองวันที่ใช้ `YYYY-MM-DD` ตามเวลาท้องถิ่น (`ymdDaysAgo` สำหรับปุ่มลัด), และ `Pagination` เพิ่มปุ่มหน้าแรก/หน้าสุดท้าย พร้อม `PageJump` ที่ commit เมื่อกด Enter หรือ blur
- **เวอร์ชัน:** `package.json` และ `package-lock.json` ปรับเป็น 2.21.0 ใน branch ของ PR ให้ตรงกับ tag
- **DB/migration:** ไม่มีการแก้ schema และไม่ต้อง migrate
- **ตรวจสอบแล้ว:** `npm run build` ผ่าน, `npm test` 352 ตัวผ่าน, `tsc --noEmit` ผ่าน และ `npm run lint` ไม่มี error ใหม่ (มี error เดิมหนึ่งจุดในไฟล์ `battle-flow.test.ts` ที่ไม่เกี่ยวกับรอบนี้) ยังไม่ได้ทดสอบ UI ในเบราว์เซอร์กับข้อมูลจริง

---

อัปเดตรอบนี้รวม PR #273 (หน้าคำสั่งซื้อรายสินค้า ค้นหาคำสั่งซื้อ ตัวกรองวันที่ และการเลขหน้า branch `feat/admin-shop-product-orders` merge commit `6bb36cb`) ตัดแพ็กเกจเป็น **tag/release v2.21.0** สรุปวันที่ 16 ต.ค. 69

# ActiveCAMT v2.21.1 🎉

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **เลือกสินค้าจากตัวกรองในแท็บคำสั่งซื้อแล้วจะเปิดหน้าของสินค้านั้นเลย** ลิงก์เปลี่ยนเป็น `/admin/shop/{รหัสสินค้า}` ตามที่คาดไว้ แทนที่จะกรองรายการอยู่ที่ลิงก์เดิม ถ้าสินค้านั้นถูกลบไปแล้วจะยังกรองในหน้าเดิมเหมือนเดิมเพราะไม่มีหน้าให้เปิด

---

## ฝั่งทีม (technical changelog)

### แก้ตัวกรองสินค้าในแท็บคำสั่งซื้อให้เปิดหน้ารายสินค้า (PR #274, merge commit `d770b43`)

- **UI:** `OrdersTab` ใน `src/app/admin/shop/AdminShopClient.tsx` ใช้ `router.push` ไปที่ `/admin/shop/[productId]` เมื่อเลือกสินค้า โดยหา id จาก `productId` ของรายการสินค้าในคำสั่งซื้อ ส่วนสินค้าที่ไม่มี id แล้วจะใช้ตัวกรองชื่อในหน้าเดิม
- **สิทธิ์เข้าถึง:** ไม่มีการเปลี่ยนแปลง หน้าเดิมยัง gate ด้วย `isShopManager` และ scope ข้อมูลฝั่ง API
- **เวอร์ชัน:** `package.json` และ `package-lock.json` ปรับเป็น 2.21.1 ให้ตรงกับ tag
- **DB/migration:** ไม่มีการแก้ schema และไม่ต้อง migrate
- **ตรวจสอบแล้ว:** `npm run build` ผ่าน, `tsc --noEmit` ผ่าน และไม่มี lint error ในไฟล์ที่แก้ ยังไม่ได้ทดสอบในเบราว์เซอร์กับข้อมูลจริง

---

อัปเดตรอบนี้รวม PR #274 (ตัวกรองสินค้าในแท็บคำสั่งซื้อเปิดหน้ารายสินค้า branch `fix/shop-product-dropdown-navigates` merge commit `d770b43`) ตัดแพ็กเกจเป็น **tag/release v2.21.1**

# ActiveCAMT v2.21.2 🎉

## ฝั่งแอดมิน/ทีมงาน (สิ่งที่ staff จะเห็น)

- **เตรียมเครื่องมือกู้สินค้าที่ถูกลบโดยไม่ตั้งใจ** ทีมงานสามารถสร้างสินค้าขึ้นใหม่จากประวัติคำสั่งซื้อ แล้วผูกรายการสั่งซื้อเดิมกลับเข้ากับสินค้า เพื่อให้การส่งมอบด้วยการสแกน Digital ID กลับมาใช้ได้ สลิป สถานะการชำระเงิน และบันทึกการส่งมอบเดิมจะไม่ถูกแก้ไข สินค้าที่สร้างใหม่จะถูกซ่อนไว้ก่อนจนกว่าแอดมินจะตรวจและเปิดขายอีกครั้ง

---

## ฝั่งทีม (technical changelog)

### สคริปต์สร้างสินค้าร้านค้าใหม่จากคำสั่งซื้อ (PR #275, merge commit `d2d9736`)

- **DB/migration:** ไม่มีการแก้ schema และไม่ต้อง migrate เพิ่มไฟล์ `scripts/rebuild-shop-products-from-orders.mjs` ซึ่งรันเองด้วยมือจาก Portainer console ใน `activecamt-app` โดยมีโหมด `--dry-run` และรันซ้ำได้อย่างปลอดภัย
- **การทำงาน:** รวมรายการสั่งซื้อที่ `product_id` เป็น NULL ตามชื่อสินค้าแบบตรงตัว สร้าง `shop_products` และ `shop_variants` ต่อหนึ่งชื่อ แล้วตั้งค่า `product_id` เท่านั้น ไม่แตะ `variant_id` ราคา สลิป สถานะ หรือ `handed_over_at` ค่าที่ตั้งให้เมื่อไม่มีข้อมูลคือสินค้าถูกซ่อน (`is_active = false`) และราคาใช้ราคาต่ำสุดของแต่ละตัวเลือก
- **PDPA/audit:** สคริปต์ไม่เขียน `audit_logs` เพราะตารางนี้เป็น hash chain ที่ดูแลโดย `AuditService`
- **เวอร์ชัน:** `package.json` และ `package-lock.json` ปรับเป็น 2.21.2 ให้ตรงกับ tag
- **ตรวจสอบแล้ว:** ซ้อมบน Postgres ชั่วคราวในเครื่องด้วยข้อมูลสมมติ ทั้งรอบ dry run รอบจริง และรอบซ้ำ ข้อมูลคำสั่งซื้อเหมือนเดิมทุกคอลัมน์ ยกเว้น `product_id` ยังไม่ได้รันกับฐานข้อมูลจริง

---

อัปเดตรอบนี้รวม PR #275 (สคริปต์สร้างสินค้าร้านค้าใหม่จากคำสั่งซื้อ branch `chore/rebuild-shop-products-script` merge commit `d2d9736`) ตัดแพ็กเกจเป็น **tag/release v2.21.2**
